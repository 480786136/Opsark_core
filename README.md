# Opsark Core

基于 Tauri 2、Vue 3 与 Rust 的智能运维需求处理桌面控制台。

首版重点实现了“需求 → 计划 → 审批 → 分步执行 → 校验 → 总结”的业务闭环；SFTP、终端、日志和模型设置作为辅助模块提供最小可用界面与适配器。

## 当前能力

- 服务器卡片管理、连接测试、基础信息与实时指标。
- 左侧远程文件区、中间 SSH 风格终端、右侧智能需求处理控制台。
- 多任务创建与切换、模型选择、四档授权等级。
- 结构化执行计划、风险标记、命令与校验详情。
- 计划整体审批，以及按风险/授权规则触发的单步审批。
- 命令输出同步到终端与任务时间线，执行后自动校验与总结。
- 任务、模型、工具、命令与系统事件审计日志。
- 模型配置、个人 Skill、执行权限和敏感变量元数据管理界面；正式版不开放系统 Skill / 底层工具编辑。
- 进入模型页自动获取并缓存 Admin 官方模型目录，官方卡片置顶；未登录也可查看，通过蒙板进入登录后使用。官方模型由平台统一配置，不提供用户参数编辑，规划使用官方接入声明的输出上限；BYOK 保留完整配置，输出预算默认留空并使用接入上限，可手动覆盖。旧版隐式 5000 规划预算会一次性迁移为留空，其他自配预算保留；旧官方参数覆盖不再加载。
- 账号入口位于外观切换下方；支持邮箱密码与可选 GitHub 登录。登录自动同步个人 Skill，不自动上传服务器、凭据库或任务日志。
- 个人 Skill 登录及增删改自动双向同步、账号绑定与版本冲突保护；免登录反馈，可留联系方式并上传 1–3 张图片；关联任务后确认上传完整脱敏日志。
- 启动异步检查版本，提供更新说明、稍后提醒和手动下载引导；不自动安装或重启。
- 远端文件数据结构获取工具，支持默认/自定义目录排除、隐藏文件、深度和节点数量限制。
- localStorage 演示持久化，Rust command 业务适配层。
- Rust `ssh2` 真实 SSH 探测与命令执行适配器，密码使用本地加密凭据库持久化，主密钥由系统凭据库保护。
- 持久 SSH PTY、交互输入、Ctrl+C 与终端输出引用。
- 真实 SFTP 目录浏览、20 MB 内小文件上传/下载、建目录、重命名、安全删除。
- 远程 CPU、内存、磁盘、网络指标采集。
- OpenAI-compatible Chat Completions 结构化计划适配器，API Key 使用本地加密凭据库持久化。
- 独立只读校验、执行/观察双状态、结构化证据和异常时模型复核。
- 敏感变量元数据、`${secret.KEY}` 指令合并、执行前输入和全链路脱敏。

## 快速启动

账号、官方模型、Skill 拆分与同步、反馈和版本引导已接入，详见 [用户体系与云能力实施方案](docs/用户体系与云能力实施方案-2026-09-17.md)。本地功能、自带模型与个人 Skill 编辑无需登录；云模型与同步需要账号，在线反馈无需登录。

系统 Skill 与工具仍在 Core 本地运行，正式版隐藏管理入口；“执行权限”控制本机 Agent 的 Shell/工具授权。进入 Core 时向 Admin 比较系统、官方 Skill 包和工具配置三类版本：系统提示官网下载；官方 Skill 与工具配置（启停、名称说明、参数默认值和约束）校验后自动缓存并生效；工具实现随系统升级。Admin 已提供对应管理入口、草稿、发布和撤回，详见方案阶段 D1。

桌面调试版默认连接 `http://127.0.0.1:8001` 的 Admin 用户 API；正式版默认连接已部署的 `https://zgspace.cn`。打包时仍可通过编译环境变量 `OPSARK_PLATFORM_URL` 覆盖固定 HTTPS 源站（不包含 `/v1`）。账号、GitHub 登录、官方模型、Skill 同步、反馈与版本检查均通过该源站访问；账号令牌由 Rust 与系统钥匙串持有，不写入前端 localStorage。

首次联调需按 [Admin 用户与额度说明](../Opsark_admin/docs/用户与额度实施入口.md) 备份并迁移数据库，然后由管理员配置注册开关、初始 Token 与可用模型。当前默认关闭注册；公开发布前必须补齐邮箱验证、找回与滥用防护。

## 演示流程

1. 在“服务器”页面打开预置的 `生产环境 · Web-01`。
2. 点击右侧“开启智能运维”。
3. 输入“检查 Nginx 配置并安全重新加载服务”。
4. 检查模型生成的步骤、风险、命令与校验说明，然后批准计划。
5. 默认“安全模式”会自动执行低风险步骤；Nginx 重载属于中风险，需要单独确认。
6. 执行完成后可在终端查看回显，在“操作日志”查看完整审计记录。

如需连接真实环境，在服务器工作台右上角点击“连接服务器”并输入密码；如需真实模型规划，在“模型与安全”中填写模型 API Key。密码、模型 API Key、敏感变量和知识库 Key 均以密文保存到本地加密凭据库，明文不会写入 localStorage、仓库或审计日志。

macOS 钥匙串和 Windows 凭据管理器仅保存通用凭据库的主密钥（服务 `com.opsark.desktop`、条目 `credential-vault:master:v1`）；官方账号的 refresh token 继续按源站独立保存在 `com.opsark.desktop.account`。增加服务器或模型只会新增本地密文记录。Rust 后端负责加解密，主密钥不通过前端 API 返回。

数据库为 `credential-vault.sqlite`，位于应用本地数据目录：macOS 为 `~/Library/Application Support/com.opsark.desktop/`，Windows 为 `%LOCALAPPDATA%\com.opsark.desktop\`。凭据值逐条使用 AES-256-GCM 加密并绑定条目标识；数据库事务保护并发保存。主密钥认证后缓存在当前 Rust 进程中。只复制数据库无法在缺少主密钥的环境中解密；主密钥缺失或密文损坏时应用保留原库并报错，不自动重建覆盖。

旧版本的 `server:`、`model:`、`secret:`、`knowledge:` 条目在首次读取或更新时迁移。新记录持久化并读回解密校验成功后才清理对应旧系统条目；清理权限不足时保留旧条目，下次访问再清理，已迁移记录始终以新库为准。删除会保留加密删除标记，防止未清理的旧条目被重新导入。启动时自动读取并迁移已配置服务器、模型和敏感变量；知识库 Key 在首次使用时迁移，未被引用的旧系统条目不会被批量删除。

## 安全说明

当前版本是业务验证版。未配置会话凭据时使用安全演示输出；配置 SSH 密码后会真实执行已批准的命令。Rust 执行器始终拦截明确的高危命令。进入生产环境前还需要完成：

- SFTP 大文件分片、远程文件编辑和传输冲突恢复；
- SSH PTY 自动重连、会话恢复和多终端标签；
- 其他敏感字段加密和密钥轮换；
- 更细粒度的命令策略和审批留痕；
- 模型 tool calling、结构化输出校验与失败重试；
- SQLite 持久化、任务断点恢复与回滚能力。

详细范围和路线见 [实施计划](docs/IMPLEMENTATION_PLAN.md) 与 [重构计划](docs/REFACTOR_PLAN.md)。

当前代码模块、调用关系和迁移状态见 [代码模块说明](docs/代码模块说明文档.md)。

步骤校验、证据链和模型复核的分阶段优化方案见
[步骤校验优化方案](docs/STEP_VALIDATION_OPTIMIZATION.md)。

只读工具遇到网络、超时或限流错误时最多尝试 3 次；重试耗尽，或环境不支持、工具不可用、输出无效时，会按当前执行模式进入方案调整，选择同目标和授权范围内的替代工具或 Shell。失败结果继续保留，替代方案仍须通过原有审批和验收。权限、凭据、执行记录故障及结果不确定的变更不会通过换工具绕过。

需求验收使用执行时绑定的服务器证据，模型与本地校验共用可引用证据列表。失败 Shell 和工具结果可用于诊断，不能作为成功验收凭据；旧记录仅在原执行身份、持久台账和原输出一致时恢复作用域。缺少完整归属的失败记录只允许引导只读取证，不能据此关闭问题或重放变更。

只读检查之后准备执行变更时，系统先根据检查的真实结果更新剩余计划；检查命令执行成功不代表端口空闲或部署条件满足。独立只读检查仍可连续运行，已完成检查进入阶段历史供后续复用。变更命令仍应自行重查可能发生竞态的前提，失败即退出，并独立验收实际目标。

官方模型和自定义模型共用同一输出契约：启用需求清单的任务必须返回需求验收字段。合法 JSON 的格式纠正只替换指定字段并重新校验，冻结原动作与工具参数；语法错误最多进行一次只读方案恢复，仍受原恢复预算限制。自动修复停止后可在原任务点击“重新生成”，无需更换模型配置；手动重试保留原需求、授权和证据，也不会重放已执行命令。更新后需重启 Core 原生进程。

协议重规划反馈包含被拒的验收命令、具体字段与匹配规则，帮助模型修正实际失败处；执行前安全检查继续生效。明确的人工重新生成会创建新的有限模型操作预算，自动续接和内部修复仍共享原预算。已确认仅因恢复上限停止的任务可手动重试；认证、额度和请求结果未知仍保留各自的处理入口。

Shell 步骤误把 `executionScope` 写入 `action` 时，合法枚举值仅在步骤外层未填写或与它一致的情况下自动归位，再经过完整契约和执行授权校验。该位置纠正不重新请求模型、不改变命令；值冲突或非法值仍会被拒绝，不猜测应采用哪个作用域。
