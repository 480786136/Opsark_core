定位：本 Skill 是领域流程参考，不是工具权限或固定状态机。工具以当前目录和用户授权为准；可复用已有证据、合并独立检查，选择有依据的等价实现，不要求先启用其他 Skill。仅依赖未知结果的步骤留待下一轮。
恢复：依据原始错误修复当前步骤；路径改变时调整剩余计划，保留整体目标与已完成证据。流程不适配时说明原因并使用通用规划；重复无进展时按系统预算暂停，保留结果和可操作原因。不绕过授权、凭据保护或执行隔离，不虚报完成。

这是数据库查询、连接诊断和受控变更的领域流程，必须以用户要求的真实数据库结果验收：
1. 先从用户需求和已有证据确认目标引擎、主机或 socket、端口、账户、数据库名与操作类型。不得把 mysql 客户端存在当作服务可用，也不得从项目示例配置猜测生产连接参数。
2. 读取连接说明只提供线索，不证明已经连接。真实连接只证明本次端点、数据库与账户可用，不能据此猜测服务端采用peer/trust等认证算法。首次显式socket账户仍需现有认证确认；只有同任务、执行会话、服务器、端点/端口、数据库、账户、客户端路径和凭据版本内的近期真实成功证据才可复用。认证失败后不得继续重试空密码或其他无证据账户。先查询当前服务器的敏感信息元数据；只有用途、目标实例和账户都一致才能复用，不把交接文档中的账户当作已授权身份。
3. 目标已确认但缺少凭据时，通过 user.request_input 安全收集；依赖输入的数据库操作在提交后规划。用户名和密码均使用 type=password、required=true，显式提供同组 credential（role 分别为 username、secret，kind=database，target 为已确认的主机:端口或 socket 绝对路径）。socket 路径保留真实大小写，不得包含变量、通配符、路径跳转或查询片段；主机名规范为小写。同组两个字段必须绑定相同目标。这是保密存储契约，用户名不是普通 text。密码使用语义唯一的 key，例如 MYSQL_ROOT_PASSWORD；禁止复用 SSH、Git、API 或其他实例的凭据。目标地址未知时先单独用普通字段询问目标位置及是否需要检查远程实例，再收集对应凭据；禁止 mysql_target 等虚构目标标识，禁止在“确认无目标实例”的表单中同时必填主机、用户名和密码。
4. 只读查询必须保留数据库客户端的真实退出码和完整必要输出。不得用 set +e、无条件 echo、接受非零退出码的 validation 或把主命令直接管道到 head/tail 将认证、SQL 或连接失败改写为成功。
5. 用户要求列出数据库、表或查询数据时，只有真实返回所需列表或结果才能完成。ERROR 1045、password authentication failed、权限不足、空输出或只证明服务存在都是阻断或中间证据，不是查询目标完成。
6. 变更步骤的 validation 在独立 Shell 中使用同一目标实例、账户和语义化敏感变量执行最小只读验收；观察步骤直接使用真实查询结果，不重复执行；不能读取 command 的临时变量或 stdout。发现查询可将“无匹配”作为有效观察，但仍必须先认证成功并真实执行查询。
7. CREATE、ALTER、DROP、TRUNCATE、写入、导入、迁移、账户/权限和认证配置修改必须按变更处理：先检查对象、数据量、依赖、备份或回滚条件，严格遵守用户授权和风险审批。不得为了恢复访问而开启 skip-grant-tables、清空密码、扩大权限或改写认证插件。
8. 客户端缺失只证明该客户端不可用；进程、常见路径或软件包未匹配不等于不存在任何实例，还可能有容器、非默认端口或自定义安装。将当前已知安装方式相关的独立只读检查合并为一个发现阶段，记录检查范围和未覆盖部分；不要重复相同检查，也不要无依据地穷举远程目标。无法定位后立即调用 user.request_input 澄清目标，不得用 shell echo 冒充向用户提问。
9. 不为寻找连接线索读取完整 shell 历史、完整环境变量或完整配置文件；只读取已有依据的目标路径和必要非敏感字段。不得输出密码、令牌、完整 DATABASE_URL 或连接串。探测无匹配与读取失败应分别记录，不能用末尾 echo 或无条件 true 隐藏真实错误。
10. 只收集完成用户当前目标所必需的数据。“列出数据库”只执行库列表查询；“列出表”只执行目标库的表列表查询。专用采集工具可核对本次实际数据库、session_user/current_user与端点，用于避免错库/错身份；这不允许账户枚举、SHOW GRANTS或额外权限审计。只读不等于可以过度采集。
11. PostgreSQL指定表核验优先使用database.inspect_postgres：传明确psql绝对路径、单一主机或socket目录、端口、数据库、账户引用和明确表清单，在一次连接的只读可重复读快照内合并数据内容摘要、列、约束、索引的采集。password模式只传usernameSecretKey/passwordSecretKey；socket_identity只在已有确认与成功身份范围内使用。TCP必须提供CA证书并保持verify-full；缺客户端、证书错误或失败不得改成免密、关闭TLS或静默安装依赖。工具没有任意SQL、写库、安装或恢复能力。
12. 备份恢复验收保留独立阶段与证据：先采源库指定表基线和明确目标存在性；经原有变更授权完成真实备份、备份文件完整性核验以及恢复到明确目标库后，在目标库合并采集同一表集合。逐表比较dataSha256和structureSha256，同时保留行数、列、约束、索引结果；行数相等不能替代内容相等，摘要缺失或截断不能判通过。源库是否保持基线须再次只读核对，若源库有并发业务写入，应说明比较窗口和限制，不能把不同时间的独立快照宣称跨库原子一致。
13. complete仅表示指定普通heap表在本次单库快照内完整采集，不等于整个数据库或业务恢复验收通过。工具明确不覆盖分区/继承、视图/外表、RLS、自定义类型及含不透明自定义类型/函数依赖的表达式；不覆盖序列状态、触发器、权限、扩展或物理备份。用户目标涉及这些对象时保留缺口并规划独立受控验收，不用“数据行数一致”掩盖。每次最多8表、每表最多10000行、读取协议最多16MiB，单行内容最多64KiB、结构每类最多256项、返回结果最多256KiB；超限应缩小明确范围或采用经审查的专用方案，不反复全量探测，也不能把部分摘要当完整摘要。
