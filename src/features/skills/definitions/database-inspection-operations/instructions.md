这是数据库查询、连接诊断和受控变更的领域流程，必须以用户要求的真实数据库结果验收：
1. 先从用户需求和已有证据确认目标引擎、主机或 socket、端口、账户、数据库名与操作类型。不得把 mysql 客户端存在当作服务可用，也不得从项目示例配置猜测生产连接参数。
2. 认证方式必须通过真实连接结果确认。可先使用已证明可用的 socket/本地系统身份进行最小只读探测；认证失败后不得继续重试空密码或其他无证据账户。先查询当前服务器的敏感信息元数据；只有用途、目标实例和账户都一致才能复用。
3. 目标已确认但缺少凭据时，下一轮只调用 user.request_input。用户名和密码均使用 type=password、required=true，显式提供同组 credential（role 分别为 username、secret，kind=database，target 为已确认的主机:端口或真实 socket 标识）。这是保密存储契约，用户名不是普通 text。密码使用语义唯一的 key，例如 MYSQL_ROOT_PASSWORD；禁止复用 SSH、Git、API 或其他实例的凭据。目标地址未知时先单独用普通字段询问目标位置及是否需要检查远程实例，再收集对应凭据；禁止 mysql_target 等虚构目标标识，禁止在“确认无目标实例”的表单中同时必填主机、用户名和密码。
4. 只读查询必须保留数据库客户端的真实退出码和完整必要输出。不得用 set +e、无条件 echo、接受非零退出码的 validation 或把主命令直接管道到 head/tail 将认证、SQL 或连接失败改写为成功。
5. 用户要求列出数据库、表或查询数据时，只有真实返回所需列表或结果才能完成。ERROR 1045、password authentication failed、权限不足、空输出或只证明服务存在都是阻断或中间证据，不是查询目标完成。
6. validation 必须在独立 Shell 中使用同一目标实例、账户和语义化敏感变量重新执行最小只读验收；不能读取 command 的临时变量或 stdout。发现查询可将“无匹配”作为有效观察，但仍必须先认证成功并真实执行查询。
7. CREATE、ALTER、DROP、TRUNCATE、写入、导入、迁移、账户/权限和认证配置修改必须按变更处理：先检查对象、数据量、依赖、备份或回滚条件，严格遵守用户授权和风险审批。不得为了恢复访问而开启 skip-grant-tables、清空密码、扩大权限或改写认证插件。
8. 客户端缺失只证明该客户端不可用；进程、常见路径或软件包未匹配不等于不存在任何实例，还可能有容器、非默认端口或自定义安装。将当前已知安装方式相关的独立只读检查合并为一个发现阶段，记录检查范围和未覆盖部分；不要重复相同检查，也不要无依据地穷举远程目标。无法定位后立即调用 user.request_input 澄清目标，不得用 shell echo 冒充向用户提问。
9. 不为寻找连接线索读取完整 shell 历史、完整环境变量或完整配置文件；只读取已有依据的目标路径和必要非敏感字段。不得输出密码、令牌、完整 DATABASE_URL 或连接串。探测无匹配与读取失败应分别记录，不能用末尾 echo 或无条件 true 隐藏真实错误。
