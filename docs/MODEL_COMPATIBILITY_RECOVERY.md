# 模型兼容与有界恢复改造

2026-09-26 更新：J0-A 已增加保守 Schema 编译与出站预检、完整本地契约复核、精确诊断和按 operation 的一次格式修复；J0-B 随后补齐 Admin 两跳错误、请求摘要冲突、官方账号状态查询及进程内跨层预算。当前实现、实际检查与下一步分别见[J0-A](../../docs/model-integration/delivery/j0-a-implementation-2026-09-26.md)和[J0-B](../../docs/model-integration/delivery/j0-b-implementation-2026-09-26.md)实施记录。本文早期测试数字为各自日期的历史记录；Responses、完整能力协商与持久台账仍待实施。

## 范围

统一现有 Chat Completions 调用的能力描述、结构契约、有效输出预算与错误恢复，覆盖 Admin 官方路由和 Core 自定义直连。保留当前协议、安全、授权、后置验收；不改服务器，不自动切换模型或扩大授权。其他原生协议不伪装为 Chat Completions，本批不实现未经测试的协议。

## 实施批次

1. Admin 输出脱敏路由能力（结构输出模式、预算、参数字段），明确地址模板不等于模型预设；监控记录请求参数、实际参数与转换原因。
2. Core 保存/传递能力信息；直连可明确选择兼容模式。集中按能力选择输出格式、处理非通用参数。所有业务入口使用各自结构契约，不能把所有响应套成计划 Schema。
3. 显式设置生成预算，独立于展示/步骤长度限制。输出截断只允许一次缩小响应的重新生成，不执行残缺内容、不拼接半份 JSON；结构错误有界修复。
4. 将格式、截断、参数/能力故障与认证/额度/网络错误区分。相同失败条件阻止无变化的重复规划；日志显示真实恢复策略和最终原因。
5. 测试能力适配、Schema/JSON 降级、预算优先级、截断恢复、参数隐私和官方/直连两条路径。保留未修改业务授权缺陷的明确边界。

## 约束

- 仅受信配置声明支持时首选严格 Schema；JSON Output 仍必须经过本地结构及业务校验。
- 已知不支持严格 Schema 时不重复探测。未知能力不意味着允许发送所有供应商扩展参数。
- 参数映射必须保持含义；无法等价映射应拒绝，不悄悄改变推理强度。
- 上游输出截断不是业务失败；历史执行证据、有效用户决定和服务器状态保持不变。
- 预算、输出模式、转换记录不包含密钥，不向公开模型目录暴露上游路由。
- 降级只改变模型调用方式，不跳过授权、安全、风险审批或验收。

## 验收

- 已声明 JSON-only 的模型不发送严格 Schema；支持 Schema 的模型首次结构化调用使用相应契约。
- 自定义未知模型不默认附加供应商专用 thinking 参数；明确配置的参数不得被静默丢弃。
- 输出预算在关闭步骤长度限制时仍显式生效；Admin 生效预算可追踪。
- 截断后最多一次紧凑重生成；失败结构化返回且相同条件不无限重试。
- 原有成功证据、失败事实、安全与授权门禁不变。

## 已实现与接入方法

- 官方路由：Admin 根据已选择的模型预设发布 `/v1/models` 的 `capabilities`；Core 在账号刷新后同步。只有供应商地址模板不会决定模型能力，仍需配置路由的模型预设。公开目录不发布上游地址、型号或凭据。
- 自定义直连：Core「模型管理 → 模型详情」选择通用、DeepSeek、千问或 OpenAI 非推理适配，再选择 JSON / 严格 Schema 能力。现有无能力配置的记录按通用 JSON 路径处理，不自动猜测供应商。
- 需求分类、计划生成、局部修复、阶段决策、结果复核、Skill 生成各有独立契约。模型配置测试使用小型 JSON 契约，不能代替真实业务联调。保存配置只校验并持久化当前模型，不调用生成接口；“测试当前模型”单独触发小型 JSON 请求（Core 输出预算至多 64 Token，仍受 Admin 路由覆盖约束），可能产生费用。自动可用性检查仅请求模型列表。
- Admin 监控详情显示请求参数、生效参数、输出模式及转换记录；Core `model-calls` 日志增加兼容尝试事件，并记录实际发送的请求。界面的旧原始请求快照仍可能是转换前参数，应以实际请求和 Admin 生效参数为准。
- 阶段/计划默认输出预算 5000，显式模型参数可覆盖；不再受「限制步骤/文案长度」开关影响。默认预算不是供应商能力上限，官方调用仍受 Admin 的 16384 安全上限及路由覆盖约束，不自动扩大预算。

## 恢复顺序与保全

1. 已知 JSON-only 不探测 Schema；声明支持 Schema 则先发严格请求。明确的能力拒绝最多降级一次，按地址、模型、凭据身份摘要、能力版本缓存。认证、额度、无效 Schema 不触发能力降级。
2. 输出截断、空内容、非法 JSON 或缺字段，最多一次精简重生成；沿用原目标、授权、证据和输出预算，不续写或执行残片。缺 `steps` 的阶段修复还检查原决策不变、步骤非空，不能改判完成消除错误。
3. 修复耗尽返回具体错误码；相同任务条件下重复点击不会再次付费请求。修改能力/模型/输出预算或真正改变阶段范围后可继续；单纯余额增加不解除格式故障。
4. 既有传输层网络/服务故障重试仍最多三次/逻辑请求；业务安全修复有自己的原有预算。本批不将这些不同层的计数混称为「总共一次重试」。

## 严格 Schema 的边界

遵循 [OpenAI 结构化输出规则](https://developers.openai.com/api/docs/guides/structured-outputs)：对象关闭额外字段，字段全部 required，可选值用 null。扩展业务元数据 `planUpdate`、`reconciliation`、`sessionContextChange`、`recovery`、`retryBasis` 在严格请求中使用 JSON 对象字符串，接收后解码并继续经过原有业务校验；JSON 模式同时兼容原始对象。严格 Schema 约束响应外壳与执行字段，不等于这些扩展内容已经通过授权或恢复验收。

本批延用已有 DeepSeek、Qwen Plus/Flash、GPT-4.1 路由预设，不声称整个供应商品牌支持同样能力。[千问官方文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output) 对 JSON 与 Schema 支持型号分别列出；其他型号应按实际能力配置。本轮 DeepSeek API 文档抓取超时，没有据此扩展支持范围。

- 历史任务的授权冲突、确认输入覆盖与旧证据时效问题未在本批修改，需要单独回归，不能把本批描述为部署全流程已彻底修复。

## 配置体验与缺漏修复（2026-09-25）

- 区分额度、兼容性与输出截断，兼容阻断直接提供模型/输出预算入口，不再误导用户充值。
- 工作区与模型管理共用编辑器；官方连接只读。编辑使用独立草稿，取消不影响已保存值；凭据写入失败不提交当前模型配置。
- 保存与测试分离，保存不会连带测试其他模型；测试只针对当前草稿，修改任意字段或密钥即使旧测试结果失效。未改动的测试成功结果随显式保存生效，官方账户可用性仍由账户服务管理。
- 规划预算始终可见；支持自定义 Token 字段、默认预算与安全上限。高级参数与当前能力联动，不支持的选项禁用，历史冲突值保留并提示清除，不静默篡改。
- Admin 向已登录 Core 发布不含上游身份的参数限制；路由预览和调用详情共用参数对比，JSON 细节折叠。预览置于保存前，窄屏纵向展示字段。
- Core 兼容事件展示生效格式、预算、Schema 降级/缓存及紧凑修复；日志投影继续排除原始请求与凭据。
- 按 redesign-existing-projects 的审核原则复用现有主题和组件，补齐窄屏按钮布局、嵌套弹窗背景禁用与关闭后的焦点恢复。
