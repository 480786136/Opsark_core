## 故障与改动

原计划把页面写入和后台启动合在一个步骤中。后台启动被拒绝后，局部修复将整个步骤替换成只读探查，却保留了依赖部署的验收。验收返回退出码 0，但证据明确显示页面不存在、端口未监听；最后的摘要只检索执行失败，误将更早的 `/var/www` 不存在列为最新阻断。

- Rust 计划生成遇到未受管后台启动时，保留整份未执行提案，交给现有有界业务重规划流程。不会局部拼入发现步骤后直接执行旧验收。
- 局部修复如果将一个包含变更的步骤整体替换成可识别的只读命令，原子拒绝替换，保留原步骤和后续步骤供重新规划。该检查不声称能判断任意 Shell 程序语义等价。
- 保留字段级修复，以及把实际只读命令的错误 `change` 标记改为 `observe` 的能力。
- 前端保存业务重规划标记，阻止旧兼容逻辑在恢复保存的错误时直接接受原计划；兼容没有该标记的旧后台启动错误。
- 失败摘要纳入显式验收失败、阻断证据和当前步骤入口的停止原因。普通未发现、非健康观察在没有明确失败证据时不自动成为阻断。原始执行状态、退出码和历史证据不被改写。
