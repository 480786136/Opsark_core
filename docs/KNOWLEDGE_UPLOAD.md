# 知识设置、任务上传与 Agent 检索

更新：2026-09-23。实现位于 `src/features/knowledge`，由 Rust `knowledge_request` 调用独立知识服务。知识凭据与 HTTP 请求不经过模型日志；检索片段作为明确标记的不可信参考加入规划模型上下文。

## 使用步骤

1. 启动平级 `Opsark_knowledge` API 与 Worker，在知识自身管理页面（默认 http://127.0.0.1:8002）登录并创建知识库，再签发该库的客户端知识 Key，赋予 `knowledge:read`、`records:write`、`records:read`。不需要启动 Admin，不能使用模型 Key 或内部服务 Token。独立管理升级方法见 [开发版说明](../../Opsark_admin/docs/独立系统开发版使用与验收.md)。
2. 在 core 桌面版设置页的“知识服务与记录上传”填写 base URL，例如 `http://127.0.0.1:8002/api/v1`，填写 Key，点击“保存并测试连接”。
3. 选择返回的目标知识库，打开“启用任务记录上传”，点击“保存知识设置”。这一卡片单独保存，不依赖页面原有的保存按钮。
4. 工作区选择任务，点击“上传任务记录”。检查脱敏后的 JSON 和目标；默认不含命令，可按需勾选脱敏命令。确认内容可上传后再提交。
5. 设置页“上传历史”可手动重试失败记录或刷新后台处理状态。接收成功不等于已发布知识；Worker 生成草稿后仍需管理员整理审核。
6. 管理员发布后，在 Core 设置开启“启用 Agent 知识检索”。每次提交需求先向所选库发送脱敏查询，后续业务规划会刷新检索；任务上方“知识参考”显示命中版本、行号和关键词降级状态。“查看当前发布原文”通过同一知识凭据读取引用，已被替换或下架的版本显示不可用。

仅 `npm run dev` 的浏览器预览不会保存 Key、连接或上传；真实使用需 `npm run tauri dev`。远程接口必须 HTTPS，HTTP 只支持 localhost / 127.0.0.1 / ::1。地址必须以 `/api/v1` 结尾，不填完整 `/records` 路径。

## 数据与安全边界

- 上传/检索开关默认关闭且相互独立；启用任一功能均需保存 Key 和选择知识库。上传仍需预览确认，关闭上传也停止状态查询。
- API Key 只存操作系统钥匙串；请求时由 Rust 读取。localStorage 只存凭据引用、配置、来源修订计数及最近最多 20 条人工确认后的脱敏上传正文/状态，不存 Key。
- 上传包含当前轮次及其阶段尝试的最近 30 步；旁问后可取最近有效执行归档。保留独立校验、失败尝试、脱敏输出节选和标明“客户端陈述”的 Core 总结；不包含完整聊天、模型请求或任意 facts。缺失历史、采集不完整及过长命令均明确标注，预期结果使用 `expectation`，不会冒充验证事实。
- 步骤和证据 ID 由执行身份生成，修订或导出窗口移动不会重新按数组下标编号。上下文只带关联执行证据中实际存在的 Shell/范围；OS 和软件版本只取与证据目标相符的服务器元数据。没有证据时不补默认环境、Shell、权限或软件版本。
- 检索限定当前所选单库，最多 5 条、合计 6000 字符；查询最多 2000 字符。网络检索超时 8 秒，客户端等待最多 9 秒，失败或无命中时继续正常 Agent 流程。结果不能扩大执行权限、替代当前服务器证据或证明整体成功。
- 返回的 URL 和标签不会直接作为导航或指令执行；客户端校验知识库、文档版本、行号及总长度，重建引用路径，用系统钥匙串凭据取原文。片段和引用以纯文本呈现。任务引用只保留在内存，最多 20 个任务，不写上传队列；修改目标、移除 Key 或关闭检索会清除引用。应用重启后再次提交需求会重新检索。
- 文本按已知密码/Key/敏感变量/服务器标识，以及常见凭据模式和 IPv4 脱敏。规则不能识别所有业务敏感信息，用户必须检查预览；不能把它当作完整 DLP。脱敏正文在本机仍是明文，敏感任务不应上传。
- 修改服务地址不会把旧 Key 自动发到新服务器：需要重输 Key、重新测试并选择库。预览后改变目标会阻止发送。请求禁止重定向，不经过环境代理；依赖代理的部署需要另行设计显式代理配置。
- 重试保持原始正文与幂等标识不变，防止响应丢失导致重复记录；限流遵守 Retry-After 秒数。重启后中断请求只转为待手动重试，不自动联网。
- 每次新预览提交递增来源修订号；同一队列项重试不递增。来源标识由任务 ID 和知识 Key 对应的安装标识共同隔离。移除本地历史不删除服务端资料，也不清零修订号。
- 本地记录损坏时暂停知识功能并保留原存储，不静默覆盖。需要开发者备份后处理 `opsark.knowledge.v1`；清空配置会丢失本机修订计数，不应复用旧来源修订上传。

## 验证

```powershell
npm run test -- src/features/knowledge
npm run build
node scripts/verify-knowledge-upload.mjs
cargo test --manifest-path src-tauri/Cargo.toml knowledge::tests --lib
```

跨项目脚本使用应用自身 Vite 解析 TypeScript 与路径别名，需要平级知识项目及其已安装依赖的 `.venv`；也可设置 `OPSARK_KNOWLEDGE_PYTHON` 指定 Python。使用合成资料、临时 SQLite 和 FastAPI TestClient，验证真实 Core DTO、服务端脱敏、幂等接收、Worker 草稿、发布索引、Core 检索响应解析、引用版本与下架 410；不访问生产数据或真实模型。

自动测试覆盖查询脱敏、越权库/非法路径拒绝、恶意 URL、引用版次校验、超时降级、迟到/取消结果隔离、后续规划刷新、纯文本引用呈现、稳定证据 ID 和环境来源。已有任务执行测试应一并运行，以验证知识检索不会改变执行和恢复规则。

桌面发布前仍需使用专用验收 Key 完成“保存 → 上传 → 整理/提炼 → 审核发布 → 需求检索 → 原文引用 → 下架”的实际 HTTP/钥匙串验收，并验证断网、密钥过期和应用重启。AI 内容质量需对真实执行日志逐条人工核对；合成契约测试不能代替真实模型质量评估。
