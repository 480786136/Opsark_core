# 知识设置与任务记录上传

更新：2026-09-07。实现位于 `src/features/knowledge`，由 Rust `knowledge_request` 调用独立知识服务，不经过模型日志或模型网关。

## 使用步骤

1. 启动平级 `Opsark_knowledge` API 与 Worker，在知识自身管理页面（默认 http://127.0.0.1:8002）登录并创建知识库，再签发该库的客户端知识 Key，赋予 `knowledge:read`、`records:write`、`records:read`。不需要启动 Admin，不能使用模型 Key 或内部服务 Token。独立管理升级方法见 [开发版说明](../../Opsark_admin/docs/独立系统开发版使用与验收.md)。
2. 在 core 桌面版设置页的“知识服务与记录上传”填写 base URL，例如 `http://127.0.0.1:8002/api/v1`，填写 Key，点击“保存并测试连接”。
3. 选择返回的目标知识库，打开“启用任务记录上传”，点击“保存知识设置”。这一卡片单独保存，不依赖页面原有的保存按钮。
4. 工作区选择任务，点击“上传任务记录”。检查脱敏后的 JSON 和目标；默认不含命令，可按需勾选脱敏命令。确认内容可上传后再提交。
5. 设置页“上传历史”可手动重试失败记录或刷新后台处理状态。接收成功不等于已发布知识；Worker 生成草稿后仍需管理员整理审核。

仅 `npm run dev` 的浏览器预览不会保存 Key、连接或上传；真实使用需 `npm run tauri dev`。远程接口必须 HTTPS，HTTP 只支持 localhost / 127.0.0.1 / ::1。地址必须以 `/api/v1` 结尾，不填完整 `/records` 路径。

## 数据与安全边界

- 上传/检索开关默认关闭。检索开关目前只保存偏好，**尚未接入 Agent 检索**。不会自动上传或自动重试，关闭上传也停止状态查询。
- API Key 只存操作系统钥匙串；请求时由 Rust 读取。localStorage 只存凭据引用、配置、来源修订计数及最近最多 20 条人工确认后的脱敏上传正文/状态，不存 Key。
- 当前记录是当前计划的前 30 步快照，不包含完整 OpsTask、历史阶段、聊天内容、模型总结、原始终端输出、原始证据或任意 facts。默认不含命令，不把步骤成功冒充整个任务成功，独立验证状态保留 unknown。
- 文本按已知密码/Key/敏感变量/服务器标识，以及常见凭据模式和 IPv4 脱敏。规则不能识别所有业务敏感信息，用户必须检查预览；不能把它当作完整 DLP。脱敏正文在本机仍是明文，敏感任务不应上传。
- 修改服务地址不会把旧 Key 自动发到新服务器：需要重输 Key、重新测试并选择库。预览后改变目标会阻止发送。请求禁止重定向，不经过环境代理；依赖代理的部署需要另行设计显式代理配置。
- 重试保持原始正文与幂等标识不变，防止响应丢失导致重复记录；限流遵守 Retry-After 秒数。重启后中断请求只转为待手动重试，不自动联网。
- 每次新预览提交递增来源修订号；同一队列项重试不递增。来源标识由任务 ID 和知识 Key 对应的安装标识共同隔离。移除本地历史不删除服务端资料，也不清零修订号。
- 本地记录损坏时暂停知识功能并保留原存储，不静默覆盖。需要开发者备份后处理 `opsark.knowledge.v1`；清空配置会丢失本机修订计数，不应复用旧来源修订上传。

node --experimental-strip-types scripts/verify-knowledge-upload.mjs
