# Skill 参考与协议恢复

## 职责边界

- Skill 提供流程、检查方法和验收建议。模型可以结合用户目标与真实证据调整步骤、阶段、工具和验收方法，不能降低用户明确要求。
- `context.tools` 由系统执行权限、工具启用状态和模型可见性决定。多个 Skill 不再求交集或并集来授予、收窄工具权限。
- 旧 manifest 和任务快照中的 `allowedToolIds`、`forbiddenToolIds`、`allowShell` 保持兼容读取，但不参与授权，也不作为工具策略发送给模型。
- 执行前仍检查当前权限、工具参数、批次协议、只读约束、凭据安全及风险审批。修改 Skill 或进入兜底不能跳过这些检查。
- 阶段投影只用于推荐当前相关说明，不是完成判断或强制前置门禁；`context.expand` 只补充说明，不解锁工具。

## 有界恢复

1. 模型返回的计划必须整体校验。允许 Shell、变更与 `read_batch` 观察工具组成有序计划，串行执行并逐步审批。`standalone` 工具保持独立；未知参数必须先取得证据。无效计划原子拒绝，不截取部分执行。失败后的逐步依赖放行尚待独立完善；当前异常复核返回 continue 时仍可能继续剩余计划，不能视为确定性的依赖门禁。
2. 后端对已解析但不合法的联合决策保留原始计划及具体校验错误，使用 `plan_protocol_failure` 跨进程传递；这不是模型服务或网络故障。
   未能解析的响应（缺字段、字段类型错误、无效 JSON、缺少正文）使用 `next_stage_response_invalid` 保留原始正文和解析错误，接入同一有界恢复入口，不转换为合法空计划或完成结论。
3. 编排器进入协议恢复后，最多生成两份新联合决策；普通调整首次命中协议错误也进入此恢复，因此最多是原始请求加两次重规划。每次请求带最新拒绝原因，保留原用户目标、执行证据和授权上下文。
4. 再次返回相同被拒计划时提前停止；服务错误、任务取消或轮次变化不触发协议重试。
5. 模型可改用当前目录中的工具、已授权 Shell 或拆成更小阶段。新计划仍须通过安全、授权和审批；计划生成成功不等于目标完成。
6. 无合法动作时接受 `adjust + steps=[]`；修正耗尽时保留结果并显示具体的工具不可见或批次冲突原因，等待用户操作，不自动循环。

普通阶段决策由现有编排入口转交协议恢复；普通调整可在同一次服务调用内接入恢复。恢复请求收紧字段级修复预算，防止重试层叠乘。暂停提示记录实际重规划次数，区分重复无进展、预算耗尽和服务错误，不再把首次拒绝统一称为“达到边界”。

针对任务 `task-1790174379771-mkhzu3` 的三项修复：

## Admin 发布与兼容

- Admin 编辑器不再显示 Skill 工具范围或 Shell 开关。旧字段仍可读取，但保存/新发布时剔除；个人 Skill 同步也不再保存权限元数据。
- 官方 Skill schema 2 表示参考流程格式，不声明硬性工具依赖；Core 兼容 schema 1 旧发布，但忽略其旧权限字段。工具自身的启停和执行权限继续独立生效。
- Core 使用 `content_protocol=3` 表示支持新 Skill 格式；Admin 仍为旧客户端分发已有兼容发布，不把新 Skill 发送给仅支持工具 schema 2 的旧 Core。
- 部署时先更新 Admin，再更新 Core。已有草稿保留；管理员可用“导入内置 Skill”确认合并新版正文，保留自建 Skill 和启用状态，然后检查、保存、发布。此按钮不自动发布。
- 正在运行的任务继续保留已固定的 Skill 快照，升级不会清空执行证据。未执行的新方案仍通过实时权限与安全检查。历史暂停任务重试前确认使用了新版 Core；不能仅发布 Skill 来修复旧二进制的误判。

本轮只修改本地代码和目录，未发布真实 Admin 内容，也未重跑远端部署。浏览器冒烟使用隔离数据库和模拟原生桥验证发布、下载、缓存及工具权限，不能代替真实 SSH 环境的部署验收。
