# Opsark 智能运维控制台实施计划

> 实施状态（2026-07-28）：P0 核心闭环已完成；真实 SSH 探测、持久 PTY、命令执行、SFTP 浏览与文件操作、实时指标、DeepSeek 计划生成、敏感变量输入/合并、独立步骤校验、失败调整和执行总结已经接入。服务器密码与模型 API Key 使用系统钥匙串持久化。当前任务支持连续多轮需求并向模型传递历史上下文；PTY 自动重连和 SQLite 迁移留待生产加固阶段。

## 1. 目标与首版范围

Opsark 是一个基于 Tauri 2、Vue 3 和 Rust 的桌面智能运维控制台。首版优先跑通“用户提出需求，系统生成计划，用户按风险与授权等级确认，系统逐步执行并校验，最终形成总结”的核心业务闭环。

### P0：必须完成

- 服务器增删改查、连接测试和基础信息展示。
- 服务器工作台：文件区、终端区、智能需求处理区、实时状态栏。
- 智能任务的新建、切换、对话记录、历史计划卡片和状态持久化。
- 模型选择与三档执行授权。
- 需求转执行计划，计划包含标题、说明、风险和可展开命令。
- 按授权等级决定自动执行或逐步确认。
- 单步执行、输出回显、结果校验、失败停止和每轮结果总结；计划、执行记录、总结分别使用独立卡片展示，记录可下拉查看命令与输出。
- 所有任务事件、模型请求摘要和命令输出进入日志，日志列表可展开查看完整详情。

### P1：简单实现

- SFTP 文件管理：提供真实 SSH SFTP 的目录浏览、上传、下载、重命名和删除；文件列表使用独立滚动容器。
- Linux 终端：提供真实 SSH PTY 的交互输入与流式输出，并过滤常见 Shell Integration/ANSI 控制标记。
- 模型管理：配置名称、供应商、模型名、接口地址，密钥保存到系统钥匙串且不在界面回显。
- 敏感信息管理：只暴露变量名和说明给模型，值单独保存；首版使用本地存储抽象。
- 用户输入工具与指令合并工具：以结构化表单和 `${secret.KEY}` 占位符完成最小闭环。

### 暂不纳入首版

- SSH PTY 多路复用、自动断线重连和完整终端仿真。
- 生产级 SFTP 大文件传输、冲突处理和权限编辑。
- 多用户、组织、RBAC、云同步。
- 任意模型协议的完整工具调用兼容。
- SQLite 数据库与其他敏感字段的加密迁移。

## 2. 核心业务流程

1. 用户创建服务器，系统进入连接测试状态；演示模式下生成基础信息。
2. 用户进入服务器工作台，系统加载文件、终端和实时指标。
3. 用户开启智能运维，系统刷新服务器基础信息和软件环境。
4. 用户选择模型、授权等级，可选中终端内容作为上下文，然后提交需求。
5. 系统创建或复用当前选中的任务，将服务器信息、实时指标、历史对话、工具描述与敏感变量元数据组成上下文；只有用户点击“新任务”才清空任务上下文。
6. 模型返回结构化计划；每步包含风险、命令、预期结果和校验方式。
7. 用户确认计划。系统依据授权等级处理每一步：
   - `observe`：所有步骤都需确认。
   - `safe`：低风险自动执行，中高风险需确认。
   - `autonomous`：低中风险自动执行，高风险需确认。
8. 后端执行命令，向终端和任务时间线发送输出，随后执行校验。
9. 校验失败时停止计划并给出调整入口；成功则推进下一步。
10. 全部完成后根据真实命令输出生成本轮总结；查询数据库、数据表、进程等场景必须在总结中列出实际结果，而不只是报告步骤数量。用户可以在同一任务继续提交下一轮需求。

## 3. 任务状态机

```text
draft
  └─ submit → planning
                 ├─ failed
                 └─ awaiting_plan_approval
                         ├─ rejected → cancelled
                         └─ approved → running
                                         ├─ awaiting_step_approval
                                         │        ├─ rejected → cancelled
                                         │        └─ approved → running
                                         ├─ validating
                                         │        ├─ failed → needs_adjustment
                                         │        └─ passed → running
                                         ├─ failed
                                         └─ completed
```

计划步骤状态：`pending`、`awaiting_approval`、`running`、`validating`、`completed`、`failed`、`skipped`。

## 4. 技术架构

### 展示层（Vue 3 + TypeScript）

- Pinia 管理服务器、任务、日志和设置状态。
- Vue Router 管理总览、服务器工作台、日志和设置页面。
- 工作台采用左中右三栏与底部指标栏布局。
- Tauri 环境调用 Rust command；浏览器开发环境调用内置演示适配器。

### 桌面与业务层（Tauri 2 + Rust）

- `server`：服务器资料、连接测试、基础信息和实时指标。
- `task`：任务状态机、计划审批、步骤执行与校验。
- `terminal`：命令执行接口和输出事件。
- `files`：远程文件接口。
- `model`：模型配置和计划生成适配器。
- `audit`：任务、模型、命令与系统日志。
- `secret`：敏感变量元数据、值存储和命令占位符合并。

服务器、任务、日志和模型元数据由前端配置存储持久化；SSH 密码和模型 API Key 由 Rust 接入系统钥匙串。Rust command 返回统一的可序列化 DTO，前端不直接依赖底层 SSH 或模型 SDK。

## 5. 风险与授权规则

| 风险 | 示例 | observe | safe | autonomous |
|---|---|---:|---:|---:|
| 低 | 查看信息、读取日志 | 确认 | 自动 | 自动 |
| 中 | 安装包、重启服务、修改普通配置 | 确认 | 确认 | 自动 |
| 高 | 删除、覆盖、防火墙/账号/磁盘操作 | 确认 | 确认 | 确认 |

无论授权等级如何，高危命令都不自动执行；只有完成步骤级单独确认后，前端才携带审批标记，Rust 后端才允许发送。未连接真实 SSH 时使用演示执行器，避免在开发机上产生意外副作用。

## 6. 数据模型

- `ServerProfile`：连接参数、连接状态、基础信息、软件环境。
- `RealtimeMetrics`：CPU、内存、磁盘、网络、采集时间。
- `OpsTask`：服务器、标题、状态、模型、授权、消息、计划、总结。
- `PlanStep`：说明、命令、风险、预期结果、校验、审批状态、输出。
- `TaskMessage`：角色、内容、类型、时间、关联步骤。
- `ModelProfile`：供应商、模型、地址、是否启用、密钥是否已配置。
- `SecretEntry`：变量名、说明、作用域、值（只在后端）。
- `AuditEvent`：类别、级别、摘要、详情、任务/服务器关联和时间。

## 7. 实施阶段与验收

### 阶段一：骨架与演示数据

- 建立 Tauri、Vue、路由、状态管理和基础视觉系统。
- 验收：`npm run build` 与 `cargo check` 通过，可进入各页面。

### 阶段二：核心智能任务闭环

- 完成任务状态机、计划生成、审批、执行、校验和总结。
- 验收：无需真实服务器与模型，也能完整演示一次成功任务和一次需确认任务。

### 阶段三：辅助模块

- 完成服务器管理、文件区、终端、日志和模型设置的最小实现。
- 验收：所有入口可操作，数据在重启应用后仍存在。

### 阶段四：联调与加固

- 校验错误状态、空状态、加载状态、权限判断和高危拦截。
- 验收：类型检查、前端构建、Rust 检查通过；README 给出启动方式与首版边界。

## 8. 后续优化路线

1. 完善 PTY 断线重连、窗口尺寸同步与完整终端仿真。
2. 接入 OpenAI-compatible tool calling，并增加 JSON Schema 校验与重试。
3. 将服务器、任务和日志元数据迁移到 SQLite，并加密其他敏感字段。
4. 增加计划版本、回滚步骤、执行快照和断点恢复。
5. 增加多服务器批量任务、审批流、策略模板和可观测性告警。
