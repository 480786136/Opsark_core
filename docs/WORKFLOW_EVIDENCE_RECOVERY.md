# 业务流与证据上下文恢复

本机制适用于所有 Shell 步骤和工具步骤，不根据业务名称、项目路径或某条获取命令判断成功。

## 决策证据

- 保留执行账本，上下文压缩只产生投影，不改写原始输出或步骤结果。
- 当前步骤每条正文最多 2048 字符；最近阶段最多 1024 字符；历史事实最多 800 字符。当前、最近及历史输出共享 12000 字符正文预算，当前步骤优先保留较新的输出。
- `contentState=complete/excerpt/omitted` 描述上下文可见程度，不表示业务成功、失败或是否执行过。
- 成功步骤同样保留有界正文。字符数、行数、指纹不能代替实际查询结果。
- 超过 2048 字符的 Shell/工具原始证据，在桌面运行且允许 `evidence.read` 时尝试保存到任务证据存储。仅保存成功且指纹一致的引用可用于补读。
- `capturedPartial/truncated` 表示采集本身不完整；即使已经读完保存内容，也不能将其当成完整远端状态。
- 历史事实携带目标上下文和证据来源，使用前必须检查目标与时效。历史命令失败保留为尝试记录，不单独作为当前目标未满足的结论；也不能因另一步成功就无条件删除失败记录。

## 自动推进

阶段完成后先判断整体目标。发现重复证据或持续取证时，下一次决策额外从本地账本补读最近三条证据，补读正文总预算 12000 字符，每条最多 6000 字符。这不是重新执行远程命令；仍被省略的内容通过有效证据引用按需读取。

进展检查独立于调整事件的命令指纹：步骤标题、命令写法、执行代次以及行数等统计变化不单独代表新事实。不同目标和实际结果仍保持区分。成功变更后允许重新观察。

当前自动推进上限：连续两个阶段没有新增执行事实、连续六个阶段没有完成变更，或本轮累计十二个业务阶段。任一上限触发时保留任务及证据，暂停自动调整，不将已完成步骤标记失败。用户明确请求调整仍可继续。传输恢复阶段不计入业务阶段数。

这套上限是通用防循环保护，不试图仅凭文本指纹推断任意业务的语义等价性，也不代替最终验收。

## 异步与取消

- 模型结果返回后检查任务轮次和 `workflowEpoch`，取消或新请求使旧结果失效。
- 倒计时及调整锁归属于捕获的轮次；旧回调不能清理或唤醒新轮次的调度器。
- 后续规划/总结异常属于任务编排异常，不反向修改已完成步骤及其执行证据。

回归测试覆盖通用短输出、长输出补读、极小压缩预算、重复事实与目标隔离、阶段上限、用户取消、复用任务以及旧倒计时返回。
