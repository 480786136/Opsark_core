# 运维执行与恢复优化方案

## 目标与边界

模型负责选择业务方案；执行器负责准确落实动作、检查授权、保留事实。
不通过增加固定业务流程或 Skill 工具限制解决执行问题；不绕过审批、凭据隔离和用户约束。
本方案只涉及平台代码与本地验证，不包含远端部署或生产发布。

## 问题依据

任务 task-1790174379771-mkhzu3 中，地图包安装成功不等于地图资源可用。
校验输出目录为空且 ls 失败，但管道末端成功使退出码为 0，导致验收误通过。
随后地图链接步骤退出 1；模型解释要求先修复，却返回 continue，执行器直接推进构建。
后端还出现仅添加依赖未修改 import 的重复构建，以及验收正则误匹配新包名的问题。

## 保留、修改、增加、删除

- 保留有序混合计划、真实工具接口、安全审批、执行记录、取消与有界协议恢复。
- 修改失败复核：继续独立步骤必须明确步骤 ID、依赖关系与依据；不能以自然语言修复建议代替动作。
- 增加失败后的轻量依赖处置：依赖失败结果或关系未知的步骤不放行；独立步骤可按序执行。
- 修复、重试和重规划必须进入已有规划与审批通道，不直接执行模型解释中的命令。
- 分离命令执行、结果验收与整体目标完成。原始 Shell 输出的未知状态不是业务成功证明。
- 删除失败后笼统 continue 放行所有步骤的行为；不把退出码 0 自动等同于目标条件满足。
- 允许根据新证据修正错误的验收方式，保留历史事实，不降低用户要求。
- 已完成结果按服务器、路径、版本复用；相关状态变化后重新验证，不重跑无关成功步骤。

## 实施顺序

### 第一批：阻止错误续跑（已完成）

1. 扩展失败复核协议，表达恢复动作和每个剩余步骤的依赖判断。
2. 执行侧验证协议并只推进已明确放行的有序步骤；旧 continue 缺少依据时进入调整。
3. 同时覆盖主命令失败、后置验收失败和未证明成功的变更。
4. 普通 Shell 后置验收不能只凭退出码免除必要的语义复核；记录独立验收结论。
5. 增加日志案例、协议兼容、后续步骤、取消与安全边界回归。

本批先沿用串行调度和现有调整入口，不建设并行 DAG，不直接执行复核返回的新命令。

### 第二批：减少无效循环（已完成）

- 局部替换受影响的剩余计划，保留已完成产物与决定。
- 重试记录状态变化或暂时故障依据；无变化的确定性失败不重复构建。
- 提供精简当前状态上下文，完整证据按引用读取；增加证据失效机制。

### 第三批：持久化恢复与体验（已完成）

- 超时、断线后先核对进程与副作用，避免重复写入。
- 模型或工具异常时有限重试、等价工具降级；无足够证据则保留现场并精准提问。
- 展示具体阻断、已保留成果与恢复入口；预算续期不清空无进展统计。
- 不自动扩大权限，不盲目回滚数据。

## 职责

Core 实现复核协议、步骤协调、验收和状态持久化。Admin 负责模型网关能力、策略配置、Skill 发布与可观测性，避免另建一套业务完成判定。
Skill 保持建议性质；本轮无需通过修改系统 Skill 来替代执行器修复。

## 第一批验收标准

- 地图链接失败 + 旧 continue 不得启动依赖它的构建。
- 模型明确给出独立步骤及依据时可以继续；到依赖或未知步骤必须停止并调整。
- 缺字段、未知步骤 ID、重复 ID、处置不完整等不能放行。
- 修复/重试动作必须落实到规划，不直接推进队列；失败事实不可改写。
- Shell 退出 0 但后置结果未证明时不能自动显示“验收通过”。
- 有效只读缺失观察不被统一当作变更失败；真正成功的结构化检查保留快速路径。
- 运行相关单元测试、类型检查与构建，并记录实际结果和未完成范围。

## 实施记录

### 第二、三批实施记录（2026-09-24）

- 增加可选局部计划更新协议：绑定原计划指纹，只替换明确指定的失败/未执行范围，保留其他待执行步骤；旧协议仍兼容整体剩余计划替换。
- 增加执行前重试检查：同一目标的同一失败变更，需引用新状态证据或有界暂时故障依据；已有成功变更不得无依据重复执行。
- 将当前有效与已失效的证据、最近失败及恢复动作汇总到精简恢复上下文；保留原始记录，供按引用读取。
- 对重启、超时、断线后结果不明的变更持久化核对事件：先允许授权内只读检查，只有引用新鲜、同目标证据的核对结论才能解除写入阻断；旧命令不能被自动重放。
- 复用已有模型网络重试与协议修复预算，不叠加无界重试。模型不可用则保存状态；工具降级必须经过原有权限、参数与风险检查。
- 展示恢复原因、保留成果与下一动作，补充单元、状态机与协议回归；不访问真实服务器、不生产发布。

#### 实际执行方式

- 普通确定性构建失败：先解释真实错误，局部替换受影响范围。可将修复、验收、重试放在同一计划；`retryBasis.afterStepIndex` 指向本次方案中前序修复/检查步骤，执行器绑定实际 ID，必须等其成功并产生证据才允许重试。不能把“计划修复”当成“已经修复”。
- 相同命令重复执行：`retryBasis` 绑定最近同目标尝试和真实证据。无变化、旧证据、虚构引用不放行；有证据的暂时性失败仅允许一次原命令重试，之后转核对/诊断，不持续消耗预算。
- 断线、超时退出码 124/137、应用重启中断：持久化 `executionReconciliation`，保留原命令、目标与证据。连接恢复后托管模式生成只读核对计划；人工模式提供“生成只读核对方案”。已明确未发送的命令仍沿用原有有界重试。
- 只读核对：模型根据事故后的同目标真实证据判断进程是否退出、产物/副作用现状。`still_running`、`unknown` 不解除写入阻断；`safe_to_retry`、`completed` 经引用检查后才可继续。仍按原权限、风险和审批规则执行，核对结论不替代整体目标验收。
- 模型/工具失败：沿用已有网络、协议恢复预算；新增恢复协议错误在同一有界决策循环内反馈修正，重复错误停止。工具可由模型选择已授权等价工具或 Shell，但不跳过安全检查。模型不可用时保留任务、现场和明确入口，不伪造成功、回滚或扩大授权。
- 局部更新归档：已完成工作只留在执行账本，不重排入队列；其他待执行步骤及其依赖判断保留。相同步骤跨阶段的最新状态覆盖旧待执行快照，待执行快照不计为执行进展或已消耗阶段预算。

#### 实现入口与边界

- `operationalRecovery.ts`：局部更新、重试依据、执行不确定性及精简状态上下文；`agentService.ts`：模型提案有界修正；`ops.ts`：持久化恢复和最终执行前检查。
- Rust 联合决策、计划转换和协议错误信封保留可选恢复元数据；旧响应不要求新增字段，未提供局部更新时仍可重规划全部剩余工作。
- 状态摘要区分当前有效观察与历史成果；同目标后续变更使旧观察保守失效，原始输出仍由已有证据归档机制按引用读取。不会因为证据摘要被截断就声称已证明。
- 本批无需修改 Admin 网关或系统 Skill 正文：沿用现有模型接口和工具目录；恢复执行约束位于 Core，Skill 仍是流程建议。未发布 Admin/Core，也未部署真实服务器。
- 重试匹配针对同服务器、相同命令文本，不声称能判断任意 Shell 等价性；不同写法的语义重复仍依赖模型及原有无进展上限。新证据的业务相关性、进程/产物结论仍由模型解释，程序引用检查不是万能业务证明。
- 当前状态失效按目标上的后续变更保守处理，未建设路径/版本级完整依赖图；历史中已缺失的原始证据不能自动恢复，需要安全补验。真实网络故障和远端部署需另行集成验收。
