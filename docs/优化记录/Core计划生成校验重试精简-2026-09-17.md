# Core 计划生成校验重试精简（2026-09-17）

## 范围与现状

本次仅优化计划生成后、命令尚未执行时的协议/安全校验修复，不涉及执行失败调整、发现后的续接规划、计费或服务器部署。

现有 Rust 已支持只发送被拒步骤、相邻标题、具体错误及裁剪上下文，本地合并后完整校验；前端协议修复也有字段白名单及调用预算。但是两条入口仍复用通用规划的长系统提示词，包含新任务发现、澄清、业务规划等无关指导。局部上下文还可能夹带旧修复计划和阶段决策。

## 计划修改

1. 为已有局部修复入口使用精简的编译修复系统提示，保留目标、用户约束、Skill、凭据、只读、真实退出码、独立验收与字段权限边界；不再附加完整发现策略。
2. 保留现有两种响应契约：Rust 内部重试返回 repair；前端发起的单次协议修复返回被拒步骤的 steps，避免相互矛盾。
3. 上下文只去掉可确定重复的历史载体：旧修复完整计划、进度指纹、阶段决策及 task 的执行历史。保留当前被拒步骤、诊断、目标、授权、确认输入、相关工具定义及必要 Skill 约束。
4. 无可解析原计划、无法定位错误的生成失败，维持原路径，不假装可以做字段修复。阶段组合冲突继续本地确定性拆分，不增加模型调用。
5. 保持原有本地合并、完整计划安全校验、字段白名单、无进展停止与调用次数上限。

## 验证计划

- 对比修复与原规划系统提示的 UTF-8 字节数（不是精确 Token，不推算真实费用）。
- 覆盖内部修复和前端协议修复的请求路由、输出契约、重复上下文剔除及授权保留。
- 运行 Rust、前端协议修复回归和类型检查；不发起真实模型或 SSH 调用。

## 实施与验证结果

已完成：

- `src-tauri/src/lib.rs`：新增专用修复提示词和入口识别；内部单步修复及前端带局部修复信封的调用使用精简提示；普通规划保持原提示。清理局部请求中的旧计划、进度、阶段决策和 task 已知历史字段，保留其他约束字段。
- 同文件：结构化错误的修复指导不再同时要求返回完整 `steps` 与 `repair`，直接使用诊断的 expected、字段白名单及单步响应契约。
- `src/services/planProtocolRepair.ts`：不向模型重复发送 nextStageDecision；原始记录留在本地，不修改其内容。
- `src-tauri/src/tests.rs`、`src/services/planProtocolRepair.test.ts`：新增提示精简、响应契约、上下文裁剪回归；本地模拟 HTTP 请求实际覆盖“初次生成失败→精简修复→合并完整计划”及前端单次修复入口。
