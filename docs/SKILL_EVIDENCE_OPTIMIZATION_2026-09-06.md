## 实际业务变化

构建和部署 Skill 的发现阶段继续允许目录发现、文件读取、用户输入与完整规则展开。完整读取并解析受支持的项目声明后，进入准备阶段，开放 software.check；读取 README、空文件、任意 JSON、截断声明都不能满足该条件。

首批支持 package.json 和 Maven pom.xml。本地适配器只生成声明格式、是否声明构建入口、是否声明运行时要求及其文件范围，不输出脚本、依赖 URL 或文件正文。识别一份声明不证明整个仓库已经识别，也不证明软件版本兼容、依赖安装、构建产物或部署成功。多项目仓库仍需根据整体目标确认实际路径。其他格式或 Shell 读取的证据可以通过 context.expand 展开完整规则继续处理。

核心编排器按声明顺序检查阶段进入条件与退出条件，支持证据类型、工具身份、完整性、精确资源范围、事实谓词和不同资源数量。后续阶段有证据不能跳过尚未满足的前置阶段；全部信息阶段退出也只恢复完整规则，不修改任务完成状态。

出现失败、主动展开、用户编辑 Skill 正文、缺失或不兼容契约时保守使用完整规则。构建和部署在实际变更后也恢复完整规则，避免环境变更使旧观察失效后又无条件重新发现项目。全局约束和最终验收在阶段投影中始终保留。

## 工具证据与复用边界

- 文件：核对工具调用身份、POSIX 路径、编码、读取字节覆盖和内外两层截断。空文件可以是完整读取，但不是有效项目声明。
- 目录：携带扫描深度、节点数、隐藏目录和排除范围；截断或警告阻止完整证据成立。“完整”仅指这次有界扫描，不表示读取了整个文件系统。
- 软件：逐名称核对覆盖情况；检查完整与全部已安装是两个事实。可执行文件存在不代表版本兼容或服务健康。
- 证据必须关联本地 main 执行记录，并与结果中的完整性元数据一致。单独的结果事实或模型文字不能推进阶段。
- 仅使用当前目标、轮次、会话及凭据版本的成功观察。实际变更使之前观察失效，同一资源的新部分读取替代旧完整读取。重复读取或工具别名不能凑足多个资源。

返回内容指纹只描述本次观察，不是远端文件版本。当前仍采用保守的目标级变更失效；资源级版本、TTL、外部修改感知与证据检索工具尚未实现。

## 上下文与 Token

模型看到全局规则、最终验收、当前阶段规则、简短阶段目录和匹配证据的引用。完整原文继续留在执行证据中，阶段元数据不再重复文件内容；阶段条件在本地检查，不增加模型调用。
