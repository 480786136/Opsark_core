# PTY 认证与授权上下文修复

## 背景

原凭据路径在申请 SSH PTY 后复用 `setsid ... &` 包装，使 Git 无法打开控制终端。另有 `git_credential_decision` 枚举因名称含 credential 被过滤，历史表单却继续引用不存在的 confirmedUserInputs；只按 Shell 文本判重也允许换包装继续失败。

## 实现

- 凭据路径保持前台运行，不再 setsid 或后台化；关闭回显失败即退出，不发送凭据。记录现有进程组，原始命令退出码完整返回。
- Agent 与普通 SSH 取消共用终止命令，先保存该执行的后代 PID 快照，再对进程组及后代 TERM 后 KILL，覆盖交互 Shell 创建的新作业组。流读取不会先关闭通道或发送 Ctrl-C 导致跟踪文件提前删除；取消后停止回答认证提示。取消命令失败不会被报告为成功。
- 后端在发事件和保存输出前流式脱敏，保留跨读取边界的匹配，包括多字节凭据；不依赖前端逐块替换。
- 新枚举提交保存经过校验的 allowedValues；旧枚举只从实际完成的来源表单核对。授权/凭据选择可以进入作用域有效的上下文；实际密码、令牌字段及秘密绑定仍隔离。
- 决策快照只对真实展开的当前有效输入发出引用，并携带对应内容。无任务上下文的独立投影仅保留来源步骤，不制造 contentRef。
- Git 认证重试按服务器、操作、仓库目标、失败原因和实际通道版本判断，不按提示文案判断。认证通道故障不因新增凭据或普通检查解锁。
- 旧执行器失败可规划一次迁移尝试，但派发时必须实际绑定新前台 PTY；若该路径仍失败，保留证据并暂停，不自动重试、不重复索取凭据。认证拒绝与缺少认证材料分别处理。
- 当前范围是可明确识别目标的 HTTPS Git 操作，不声称任意 Shell 程序语义等价。未识别命令仍接受原安全校验与执行检查。
- 匿名/非交互探测未尝试注入凭据，其缺少终端不能证明已绑定 PTY 损坏；仍允许第一次正常收集凭据，不把防重复机制变成禁止首次授权。

## 验证与上线

运行 `npm run check`、`npm test`、`cargo test --lib`。POSIX PTY 回归使用 Python 标准库和虚构凭据，验证 `/dev/tty`、不回显、非零退出码，以及忽略 TERM 的子进程仍被取消清理。

本地回归不等于真实 SSH/Gitee 联调。发布需重新构建并启动 Core（包含 Rust 后端），随后用已有授权做一次真实克隆验收；不需要用户为通道故障重新提交同一凭据。若故障仍在，应保留原退出码和证据停止自动推进，修复实际执行通道后再恢复；不得用日志文案、补录凭据或通用检查冒充修复。

本轮本地结果：TypeScript 检查及前端生产构建通过；前端 154 个测试文件通过（1,689 项通过、16 项跳过）；Rust 187 项通过、2 项真实服务联调测试忽略。PTY 测试另覆盖忽略 HUP/TERM 的交互式作业组，确保取消不依赖 Shell 自动传播信号。未使用真实服务器凭据进行联调。
