# 认证与证据契约修复说明

日期：2026-09-15。范围：Core 凭据契约、工具协议修复、认证证据复用、执行证据分类。

## 1. 修复目标

针对 `task-1789398849313-yj7lwb` 暴露的链路问题修复基础契约，不加入“某个数据库/某个容器应该怎么操作”的业务特判，也不重构任务、终端或审批状态机。

### 凭据目标契约

- 数据库 `credential.target` 统一使用已确认的 `主机:端口` 或 socket 绝对路径；主机名规范为小写，路径保留大小写和合法空格。
- socket 路径拒绝控制字符、变量、通配符、路径跳转、查询片段；目标不得携带明文凭据或 URL userinfo。
- 同一组用户名和密码必须绑定相同 kind/target，均为必填密码字段。普通选择字段不参与凭据存储。
- 工具目录、严格解析、凭据配对存储和内置数据库 Skill 使用同一规则。目录版本更新为 7，数据库 Skill 版本更新为 3。
- 已有凭据不迁移、不删除；旧的缺少端口/不明确目标不会被程序猜测补全，复用不确定时需确认。

### 协议错误只修协议

- 前端工具表单格式校验失败后只进行一次局部协议修复；初次需求的 intent、relation、Skill 选择保留，不再次调用需求分类。
- 保存原始模型计划、首次字段错误及修复错误；禁止工具替换、改写标题/描述/风险/预期/校验、改变步骤数量或修改无关命令。定位到字段的错误还检查无关参数不变。
- 修复仍失败时进入人工等待，关闭自动调整；手动重试使用保留的协议修复上下文，不采用缓存的下一阶段业务计划。
- 初始规划、发现阶段延续、调整规划、联合下一阶段决策均保留协议失败边界；不能因工具参数错误退回整体业务重规划。
- 本次不把协议格式错误解释成真实服务器执行失败；没有执行的计划不会获得成功证据。

### 认证证据复用

| 观察到的错误 | 记录分类 | 不得推出的结论 |
| --- | --- | --- |
| 连接拒绝、超时、DNS 失败 | connection_failed | 密码错误 |
| 来源主机不允许连接、主机密钥/证书拒绝 | route_rejected | 应更换账号或清空密码 |
| 未提交密码、无法交互取凭据 | material_missing | 已保存凭据无效 |
| 已提交的认证组合被拒绝 | authentication_rejected | 一定只是密码错误 |
| SQL/资源操作权限不足 | permission_denied | 应自动切换管理员或扩大权限 |

- 认证证据绑定任务、步骤、执行来源服务器、实际端点、连接方式、账号引用、凭据键、时间及凭据修订，不记录明文密码或完整查询结果。
- 任务保留最近 32 条，关联凭据元数据保留最近 8 条；复用候选有效期为 30 分钟。历史成功只说明当时组合可用，不保证下一次连接成功，也不授权删除或其他变更。
- 凭据变动、服务器连接配置变动会使已有认证缓存失效。主命令和独立校验分别记证据。
- 同一被拒组合没有新凭据/证据时不自动重试；新身份、未经证明的免密/隐式认证、TCP/socket 范围不符进入既有步骤审批，明确显示原因并等待。
- 确认只对应本次任务轮次、服务器、会话、凭据版本、命令及校验内容，消费后失效；托管模式不能自动代为确认。
- 认证和权限错误不进入“等待后置状态稳定”的重复校验。
- 规划、阶段决策、失败复核上下文携带认证证据及凭据引用；开发者日志新增 `authentication_evidence`，可关联主命令或独立校验。

**当前识别边界：**可靠的端点/账号抽取覆盖简单的 mysql、mariadb、psql 客户端调用，不是完整 Shell 解释器。复合脚本、默认配置文件、重复连接参数、无法核对的协议覆盖，不生成认证成功证明；使用已知凭据引用等可识别的不确定调用进入人工确认。未经识别的任意程序/脚本并没有因此获得全协议认证防护保证，后续应由工具的结构化输入输出契约补充，而不是继续堆叠业务关键词。

### 执行证据分类

- 普通 Shell 一律保留原始 `command` 证据；标题、描述、文件名出现 mysql/java 等字样，不再决定 SQL/进程等领域解析器。
- `lineCount` 仅代表原文行数，不再伪造 SQL `rowCount`、数据库存在性或进程归属。
- 主命令与校验分别解析和存储，校验输出不能覆盖主命令事实。
- 未解释输出记为 `unknown`、`interpretation=raw`；这不单独构成执行失败，也不意味着整体目标成功。真实失败退出、后置校验失败及明确阻断仍保留，整体目标仍走原有复核。
- 领域结构化解析器保留作为显式契约的扩展点，不再按任意 Shell 的关键字自动启用。历史已落盘证据不追溯改写，请用新任务验证。

## 2. 建议人工回归

使用专用测试实例；本次开发验证没有连接或修改用户数据库，也没有执行卸载、删除或重启业务。

1. 让 Core 查询测试数据库列表：保存的 TCP 凭据被来源策略拒绝后，应保留拒绝原文，不应直接判定密码错或自动换 root 免密。
2. 已发现正确 socket 后输入合法用户名/密码：带普通选择器和两个密码字段的表单应能一次通过；预览中的 socket 大小写不应改变。
3. 在认证确认停留一分钟并切换任务再返回：不得自动派发命令；显式确认后只执行一次。改变端点或命令后应重新确认。
4. 查询 `/var/lib/mysql/mysql.sock`、配置中的端口或进程信息：只能形成配置/原始执行证据，不能把输出行数当作数据库数量。
5. 测试模型返回非法工具字段并在修复时改写 description：应显示首次和修复错误，保留原始计划，停止自动调整；手动重试仅修协议。
6. 校验返回来源拒绝、未提交密码或权限不足：不得连续执行四次“状态稳定”校验。
7. 修改服务器地址或更新凭据后重试：旧认证成功与旧审批不得静默复用。
