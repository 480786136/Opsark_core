## 2. 已确定的产品行为

- Core 启动直接进入本地工作台，不创建匿名用户，不要求注册。
- 服务器、终端、SFTP、任务、本地自定义 Skill 和自备模型（BYOK）继续免登录使用。
- 系统（官方）Skill 和工具仍在 Core 本地运行，正式版隐藏其管理入口；Admin 负责官方内容发布、版本信息与工具启停、参数配置。
- 每次启动进入 Core 后异步向 Admin 检查系统版本、官方 Skill 包版本和工具配置版本。系统有更新时提示前往官网下载；兼容的官方 Skill 更新到本地；工具可同步启停、名称说明和已有参数配置，实现代码随 Core 安装包升级。
- 调用 OpsArk 官方模型、同步自己的 Skill 时要求登录。
- 注册成功按当时的 Admin 初始额度策略发放一次额度；修改策略只影响后续注册。
- Admin 可以增减单个用户的剩余额度，必须填写原因并保留账本。界面如提供“设置剩余”，后台也必须按当前版本计算调整差额，不能覆盖并发消费。
- 额度不足只暂停新的官方模型请求，任务保留已执行证据；用户可补充额度或明确切换 BYOK 后继续，不能重放已完成命令。
- 登录不上传本地任务、服务器、凭据库或日志；按同日最新要求，个人 Skill 改为登录及增删改自动同步，诊断上传仍需确认。首次登录关联本机未绑定的个人 Skill；已有账号归属保持不变。详见 [个人 Skill 自动同步](优化记录/Core个人Skill自动同步-2026-09-17.md)，本文下方显式上传的阶段记录为历史实现。
- Knowledge 继续独立运行，用户反馈不自动进入知识库。

## 3. 身份与本地数据

Admin 内新增终端用户与用户会话，和现有 Admin/管理 Cookie 会话分离。Core 通过固定的平台 HTTPS 地址请求用户 API，调试版允许 loopback HTTP，禁止向用户自填模型地址发送账号令牌。

访问令牌短期有效并由 Rust 持有；刷新令牌仅在系统钥匙串中保存，不通过通用凭据 IPC 返回前端。刷新时轮换；退出撤销会话并清除本机令牌。登录界面仅获取当前用户的安全投影和余额。

本地工作台是设备本地空间，与云账号空间分别存储。登录不接管已有服务器和凭据；云 Skill 缓存以服务端用户 ID 隔离，退出后不能被下一账号读到。后续需要把本地业务数据从 localStorage 迁移至事务存储，保留显式迁移和恢复路径。

第一阶段提供邮箱标识+密码注册/登录和管理员控制的注册开关，注册默认关闭。公开注册前完成邮箱验证/找回、滥用控制和设备会话管理；内测可在受控环境开启。注册码、邮箱供应商、额度数量和部署域名由实际运营配置，不写入源码中的生产默认值。

## 4. 额度契约

第一阶段计量单位为 Token：输入 Token + 输出 Token，一单位扣一个 Token，界面明示口径。不同模型的成本权重/缓存价需要未来以版本化计价规则迁移，不在本阶段暗中加权。

建议对象：UserAccount、UserSession、CreditAccount、CreditLedger、ModelReservation、RegistrationPolicy。金额/Token 全部使用整数。

- 注册：账号、额度账户和初始赠额在同一事务内创建，赠额策略版本与数额写入账本。
- 调整：原子修改可用余额，追加流水，记录管理员、原因和幂等键；余额不能小于零，不动正在预留的额度。
- 请求：网关按用户身份校验模型范围和最大输出，原子预留额度，防止并发透支；客户端余额只作展示。
- 结算：服务端根据供应商实际 usage 扣款，多余预留释放；缺失 usage、流式中断或发送状态未知进入待核对，不能当免费请求自动释放。
- 重试：同一幂等键不得再次产生上游调用或重复扣费；超时后先查询原调用状态。
- 用户历史只显示自己的流水和请求；Admin 变更须审计，较大/敏感调整后续加入审批阈值。
- 供应商密钥只保存在 Admin 服务端；用户不需要复制平台模型 Key。

官方请求由 Admin 网关默认采集请求输入和模型输出，不依赖用户主动上传反馈。使用现有 `MODEL_CALL_CAPTURE_ENABLED` 服务端开关；快照脱敏加密、仅管理员详情可见且查看留审计，默认 7 天保留期、每侧 64 KiB 上限。登录本身不上传本地任务/日志，BYOK 直连不经过 Admin，因此不在采集范围；历史未采集正文不能补回。自动脱敏不能保证覆盖全部敏感信息，发布时需同步官方模型的数据使用说明。

## 5. Skill 与工具边界

系统 Skill 为只读平台发布物，用户 Skill 为用户自己的声明式工作流，工具权限由可信执行端最终约束。系统 Skill 的“只读”指用户不能编辑官方定义，官方仍可通过独立发布通道更新。保留用户 Skill 的本地编辑与导入导出；个人云同步自动同步当前账号关联的用户 Skill，与免登录的官方内容更新分开。

正式版不向普通用户提供系统 Skill/底层工具的编辑页；隐藏入口不删除 Core 中的定义、注册表和执行器，也不把任务执行迁移到 Admin。用户管理自己的 Skill，仍可看见任务即将执行的操作、风险与授权确认。开发版保留工具调试入口。旧系统 Skill overrides 备份到 `opsark.skillConfiguration.v03.backup`，转换为停用的用户迁移副本，不改写官方系统定义。正式版不加载旧工具定义 overrides，也不删除这些旧数据。

### 5.1 执行权限的用途

“执行权限”回答的是“本机允许 Agent 使用哪些能力”，与“官方提供哪些工具、工具是否启用”和“系统 Skill 如何编排操作”分别管理：

| 控制 | 谁维护 | 作用 |
| --- | --- | --- |
| 系统 Skill | 官方通过 Admin 发布，Core 加载 | 定义工作流、指令、能力需求与版本 |
| 工具实现 | Core 安装包 | 提供实际可执行的能力、参数协议和校验 |
| 工具配置 | 官方通过 Admin 发布，Core 缓存 | 决定哪些内置工具可供 Agent 使用，并提供工具说明、参数默认值和取值限制 |
| 执行权限 | 本机用户 | 控制 Agent Shell 与原子工具授权范围 |
| 任务审批 | 本机用户及现有风险规则 | 确认本次计划、具体步骤是否允许执行 |

例如，Core 内置某个文件工具且官方启用了它，本机用户仍可禁止 Agent 调用；官方停用该工具后，本机授权也不能重新开放它。官方更新不得覆盖用户的授权选择。执行权限页面不提供工具代码或系统 Skill 编辑能力，是否单独保留入口属于界面安排，不影响执行层检查。本次先明确职责，不据此删除已有入口。

目标规则是：可派发工具 = Core 已实现且兼容的工具 ∩ 官方启用范围 ∩ 本机授权范围 ∩ Skill 允许范围，并通过现有任务审批。未声明限制的旧 Skill 沿用兼容规则，显式禁止优先。工具清单不等于 Shell/文件/网络权限；必须同时覆盖命令执行路径，不能只缩小模型可见工具列表便声称隔离完成。兼容旧数据时保留原始副本并明确迁移，不静默删除用户修改。

云同步使用 `base_revision` 乐观锁、幂等 mutation、删除墓碑和显式下载副本；不用客户端时间戳覆盖另一设备修改。系统更新不能覆盖用户 Skill。任务固定已激活的 Skill 内容与版本快照；全局权限收紧则在下一次派发复查并暂停，不被旧任务快照抵消。

当前已实现的权限是全局 Agent Shell 开关与原子工具授权列表，再与用户 Skill 请求取交集，规划和执行均检查；AgentSession 的 Shell 入口还有 Rust 校验。Admin 已发布的工具启停配置现已接入模型可见清单、控制器派发与工具执行器检查。保留既有审批与危险命令防护。**这不是操作系统沙箱**：允许 Shell 即可能访问文件和网络，关闭某个工具不能阻止 Shell 使用同等能力；手动终端不受 Agent 开关限制。已发出的命令不会因切换开关自动中断。

## 6. 联系、问题反馈与 Admin 联动

帮助页采用左侧问题反馈、右侧联系与系统信息的两栏布局。反馈无需登录，可选填联系方式并上传 1–3 张 PNG、JPG、WebP 图片（每张不超过 5 MB）。匿名提交不创建账号；登录用户可查看账号工单、支持回复和删除正文，匿名工单通过所留联系方式跟进。

关联任务后自动获取该任务全部运行、开发和模型调用日志，包括本地磁盘 JSONL 历史分卷与当前内存记录；不再限制为最近 20 条或 16000 字符摘要。点击提交时弹出“温馨提示”，说明日志范围、仅用于问题分析与处理及保存 30 天，确认后才读取并上传，取消不提交。完整日志上传上限为 64 MB，超限或读取失败明确报错，不会静默截断。网络失败重试使用同一快照与 mutation_id，避免重复工单。

客户端脱敏已知凭据，服务端校验字段、附件数量/格式/大小及敏感模式。正文、联系方式、图片、日志及回复加密保存，30 天后清理；管理员读取/回复留审计，支持下载完整日志。反馈不会自动进入 Knowledge。匿名反馈按来源 IP、账号反馈按用户限流，每小时最多 10 次。过期清理继续使用 `app.maintenance`。

默认微信 `zgkjkj`，邮箱 `zgkj@zgspace.cn`，开发者 `智明`。Admin 可修改这些字段；Core 启动及手动检查版本时通过公开 `client-info` 同步，即使没有新版本也会更新。相同内容不重复写入，离线保留最后一次有效联系人，首次使用展示内置默认值。部署 Admin 前执行 `alembic upgrade head`，新增 `0008` 迁移允许匿名工单并补齐联系字段。

## 7. 版本更新与引导

### 7.1 三类版本分别处理（修订后的目标行为）

Core 启动进入工作台后，先加载本地已生效的官方 Skill 和工具配置，再异步调用 Admin 对比三类版本；支持手动重试检查，系统升级提醒可稍后处理。更新接口允许未登录只读访问，不据此创建用户。无网络或服务端不可用时保留本地可用版本，不阻塞工作台。

| 类型 | 本地内容与版本含义 | Admin 返回 | Core 发现新版本后的行为 |
| --- | --- | --- | --- |
| 系统版本 | 已安装 Core 应用版本 | 适用平台/架构的最新系统版本、说明、官网下载地址 | 提示用户前往官网下载并手动安装；不自动替换应用 |
| 官方 Skill 版本 | 已激活的官方 Skill 包版本，包内保留各 Skill 自身版本 | 兼容的官方 Skill 包版本、内容下载地址、SHA-256、所需 Core/工具版本 | 自动获取并校验声明式内容，成功后保存为本地官方版本；不覆盖用户 Skill |
| 工具版本 | 官方工具配置版本；每个工具的实现版本仍由 Core 自带 | 配置版本、内置工具 ID、启用状态、名称说明、参数协议及兼容要求 | 同步启停与兼容参数配置；执行代码、新参数和新能力随 Core 升级 |

三个版本独立比较。系统无需升级也可以更新官方 Skill 或工具参数、启停配置；工具配置变化不必重新下载未变化的 Skill 包。Skill 需要更高 Core/工具实现版本时，保留当前兼容包并提示先升级系统，不能只改版本号便声明更新成功。

### 7.2 检查接口与版本约定（已实现）

沿用公共 `GET /api/core/v1/client-info`，保留现有联系信息、最低云版本和 `latest` 发布记录，扩展官方内容信息。现有接口契约如下：

| 字段 | 约定 |
| --- | --- |
| 请求 `platform`、`arch`、`version` | 沿用现有参数，`version` 是当前 Core 应用版本 |
| 官方内容版本比较 | Core 保存当前已激活版本并在本地比较；检查接口返回最新兼容发布，当前实现不需要上传本地内容版本 |
| 响应 `latest.version`、`latest.download_url` | 新系统版本与官网下载地址；无适用系统更新时 `latest` 仍为 `null` |
| 响应 `system_skills` | 官方 Skill 发布的 `id`、`kind`、`version`、`download_path`、`sha256`、`min_core_version`、说明；无适用发布时为 `null` |
| 响应 `tools` | 工具配置发布元数据，字段与 `system_skills` 相同；无适用发布时为 `null` |
| 内容下载 `/api/core/v1/official-content/{kind}/{id}` | 返回发布元数据和 `content` JSON 字符串；SHA-256 校验该字符串 UTF-8 字节。正文含 `schema_version`、`kind`、`version`、`min_core_version`、`required_tools`、`items`；工具协议 v2 的项包含 `id`、`enabled`、`min_implementation_version`、`name`、`description`、`usageInstructions`、`outputDescription`、`inputSchema` |

Core 系统版本继续按三段数字比较，不按字符串排序；官方 Skill 包版本、工具配置版本分别使用单调递增的发布整数，包内 Skill/工具实现版本不能充当整个发布包的版本。相同版本不重复应用，较低版本不自动降级；需要恢复旧内容时发布更高配置版本。同一发布版本的内容不可原地修改。

Admin 按平台/架构/版本选择系统安装包，按最低 Core 版本及 `content_protocol` 选择官方内容发布，Core 再验证兼容性。新版 Core 传 `content_protocol=2`；不传时默认为 1，仅返回旧版可识别的内容。Skill 包仍使用 `schema_version=1`；新的工具包使用 2，历史工具包 1 仍可读取。内容包中的 `required_tools` 明确 Skill 依赖的工具 ID 与最低实现版本；工具配置只能作用于 Core 已知且版本满足要求的内置工具。缺少字段、无发布或请求失败不表示撤销本地内容；停用必须通过有效的新配置显式表达。旧客户端可继续读取原有字段。

### 7.3 本地更新与生效规则（已实现）

1. **本地可用**：安装包携带官方 Skill 基线、工具实现和默认启停配置；曾成功更新后优先加载已验证的本地官方版本。官方缓存与用户 Skill、按账号隔离的个人云同步缓存分开，退出账号不清除官方版本。
2. **官方 Skill 更新**：经固定 Admin 发布源获取，校验版本、内容哈希、格式与依赖后再激活。只分发 Core 支持的声明式指令、规则和工作流数据；执行器、解析器和工具代码继续由安装包提供。不接受远程 `planningContract`。官方指令与能力声明和编译基线完全一致时沿用本地阶段合同；修改后使用完整指令规划，不能继续套用旧合同。个人 Skill 同步接口不能写入此通道。
3. **工具配置更新**：可改变指定内置工具的启停、名称说明、已有参数的说明、默认值、必填项、枚举、数值范围和长度/数量限制。参数名称、类型及内置执行协议保持兼容，不能放宽内置硬限制或移除 Core 必需参数。Admin 保存及 Core 激活时均递归校验；远程 `implementation` 和脚本不被接受。未知 ID 或实现版本不满足时不激活对应能力。官方启用不等于用户授权，不修改本机执行权限。配置中缺失的工具不据此自动开放。
4. **生效时机**：完整下载、校验并持久化成功后才记录新版本，Rust 按固定 Admin 源站隔离缓存，临时文件写入完成后原子改名为不可变发布文件，失败保留上一份有效内容。两个通道独立更新，先应用工具配置，再更新 Skill，Skill 失败不撤销已生效的工具停用；下一次派发复查，被停用工具阻断时说明原因。参数默认值只填充未传入的字段，保留显式 `false`、`0` 和空字符串；参数解析及派发均使用当前配置，执行适配器整理后的实际请求也复查约束。已发出的调用不追溯修改。
5. **任务稳定性**：运行中任务继续使用已固定的 Skill 内容与版本快照；新任务或尚未激活 Skill 的任务使用新版本。工具停用及本机权限收紧仍作用于下一次派发，不被旧快照绕过；已发出的操作不自动中断。
6. **反馈与重试**：系统更新展示官网下载入口；Skill/工具配置更新完成可显示简要状态，失败说明仍使用哪个本地版本，并允许重试。离线使用最后一次有效配置，不宣称能对离线旧客户端即时撤销能力。

### 7.4 现有实现与后续范围

当前代码已实现 **Core 应用版本检查与下载引导，以及官方 Skill/工具配置独立发布与同步**。系统安装包仍采用以下引导：

| 类型 | 引导 |
| --- | --- |
| 普通更新 | 展示版本与改动，可稍后提醒 |
| 前往下载 | 重新获取发布记录，确认未撤回后打开官方配置的 HTTPS 下载地址；提示结束任务、传输并保存工作后手动安装 |

### 工具参数更新补充（2026-09-17）

- Admin → 工具管理 → 展开“编辑工具配置”：修改工具名称、说明、使用说明、输出说明或参数 JSON；保存草稿后填写发布说明并“保存并发布”。错误 JSON 和不兼容协议不会写入草稿。历史内容可复制后重新发布更高版本。
- 例如 `files.read_content.inputSchema.properties.maxBytes` 可将 `default` 从 65536 改为 4096、`maximum` 从 262144 收紧为 16384；同步后未传 `maxBytes` 的调用实际使用 4096，超过 16384 的调用在执行前被拒绝。删掉可选参数的默认值后，适配器的内置回退值仍须满足当前约束，否则拒绝执行。
- 参数更新递增工具包配置版本，保留 Core 中的实现版本；模型上下文同时获得更新后的名称、说明、参数和 `configurationVersion`。新参数名称、类型或执行能力需要先修改 Core，再重新导出官方目录。
- 旧版仅启停草稿会补齐内置元数据；更新目录时保留兼容的参数修改，发现不兼容时显示警告与新目录默认参数，保存前不改写数据库。无需为本次参数扩展新增数据库迁移；需重新构建 Admin 前端、重启 Admin 并重新编译 Core 原生端。
- 本次验证：Core 全量前端 1372 项通过、16 项跳过；Admin 全量 134 项通过，随后补充 null 输入拒绝用例，官方内容定向 34 项通过；两端生产构建及 Ruff 检查通过，Rust 官方缓存/协议测试 3 项通过。浏览器使用隔离 Admin 数据库和模拟原生桥验证参数编辑、错误 JSON、草稿刷新、发布、旧协议兼容、模型上下文、实际派发默认值/超限阻断及缓存重载，未访问实际服务器或发布到现有业务库。
