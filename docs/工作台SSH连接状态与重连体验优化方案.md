# 工作台 SSH 连接状态与重连体验优化方案

- 编写日期：2026-09-13
- 适用范围：Opsark Core 服务器工作台，包括服务器标签、SFTP、终端、智能需求处理及指标栏。
- 文档状态：核心逻辑与界面已实施，实施记录见第 11 节；真实断网、恢复及桌面视觉效果待实机验收。
- 依据：实施前代码审计、用户提供的断线截图及实施后的自动化测试。第 2 节保留实施前的问题说明，不代表当前代码仍存在这些问题。

## 1. 优化目标

统一每台服务器的连接状态，解决“终端已断开，服务器标签仍为绿色、SFTP 仍显示目录、智能需求仍可发送、指标仍显示实时采集”的状态矛盾。

目标包括：

1. 断线能够被及时发现，并同步更新服务器标签及所有相关面板。
2. 首次连接、自动重连、手动重连和认证失败都有明确、统一的界面。
3. 未连接时阻止新的远程操作，但保留终端历史、任务记录及输入草稿。
4. 重连过程中连接提示持续存在，不允许重复发起连接或误操作。
5. 指标和目录明确区分实时数据、离线缓存及无数据，避免跨服务器串值。
6. 保留现有深色工作台布局，以紧凑、清晰、适度科技感的方式完善状态反馈。

## 2. 当前行为与根因

| 用户观察 | 当前实现与问题 |
| --- | --- |
| 终端已经报错，服务器标签仍亮绿点 | 终端断线事件只更新终端窗格，没有统一更新服务器在线状态。 |
| “真实 SSH 会话”仍然显示 | 该提示依赖在线 ID 列表，旧记录可能未清除，不代表连接当前仍可用。 |
| 突然断线多久能知道 | 当前没有带响应截止时间的统一健康检测，无法保证发现静默断网的时间。 |
| 多次失败后只在右下角提示手动重连 | 自动重连主要属于终端面板，其他模块没有共享同一重连流程。 |
| 断线后仍能看到 SFTP 目录 | 为保留浏览上下文缓存了目录，但离线标识依赖未及时变化的全局在线记录。 |
| 未连接时智能需求输入框仍可使用 | 输入框主要根据任务是否忙碌禁用，提交和远程执行入口也缺少统一连接约束。 |
| 密码错误缺少直接提示 | 错误写入日志，但连接表单没有完整的行内错误反馈。 |
| 断线后仍显示“实时采集中” | 采集失败保留旧样本，而底栏无条件显示采集中。 |

### 2.1 连接检测与重试的现有限制

- 终端在读取、写入或 EOF 时发现连接异常；网络静默丢包时，不能只靠该机制及时发现。
- 终端循环的短轮询间隔，不等于网络断线检测时限。
- 当前 TCP 建连和 socket 超时配置，不等于完整 DNS、SSH 握手、认证及会话建立的总截止时间。
- 当前终端自动重连最多连续尝试 3 次，等待间隔为 1、2、4 秒，实际总耗时还包括每次连接耗时。
- 当前收到连接成功事件就清空失败次数，反复“连上即断”可能持续循环。
- 每 10 秒采集指标并不是可靠的连接心跳，指标失败也不会统一标记离线。

### 2.2 需要优先处理的数据正确性问题

1. `refreshServer` 失败只更新服务器状态，可能残留 `connectedServerIds`；后续连接检查会直接使用旧记录。
2. 保存新凭据时依赖上述在线记录，存在认证失败后仍按旧在线状态保存错误密码的路径。
3. 远程指标缺少凭据时会回退到 `get_realtime_metrics()`；该函数根据时间生成合成指标，并非真实本机采集。
4. 多台服务器共用一个前端指标对象和加载锁，切换服务器时可能显示上一台服务器的数据。
5. 智能任务也可能读取该公共指标，导致任务上下文包含其他服务器的数据。

以上说明存在错误路径，不据此断言用户截图中的具体指标一定来自合成数据。

## 3. 统一连接状态模型

### 3.1 服务器级状态

每台服务器维护独立、权威的连接状态，服务器标签、顶部提示、面板和指标统一订阅。不要继续独立修改多份在线标记。

| 状态 | 标签及顶部提示 | 工作台行为 |
| --- | --- | --- |
| 尚未连接 | 灰色 · 未连接 | 显示等待连接界面及连接入口。 |
| 正在连接 | 蓝色动态标记 · 正在连接 | 显示真实连接阶段，阻止远程操作。 |
| 已连接 | 绿色 · SSH 已连接 | 根据各通道就绪状态恢复功能。 |
| 连接异常待确认 | 黄色 · 正在确认连接 | 暂停派发新远程操作，保留现有内容和在途任务状态。 |
| 正在重连 | 蓝色动态标记 · 正在重连 | 保持连接蒙板或只读提示条，显示次数和耗时。 |
| 重试耗尽 | 橙色 · 需要手动重连 | 显示原因、重连及修改连接信息按钮。 |
| 认证失败 | 红色 · 身份验证失败 | 展示凭据编辑入口，不重复尝试已失败的凭据。 |
| 用户主动断开 | 灰色 · 已断开 | 不自动重连，保留历史查看和手动连接入口。 |

“真实 SSH 会话”替换为实际状态文本；悬停或键盘聚焦时，可查看最近成功响应时间、失败原因和重试次数。不能只依赖颜色传达状态。

断线只改变对应服务器的状态，不自动切走用户当前查看的服务器。

### 3.2 服务器状态与通道状态分层

- 服务器级状态描述网络、身份验证和基础 SSH 会话是否可用。
- 终端窗格、SFTP、指标分别维护加载、就绪、失败等通道状态。
- 单个 Shell 正常退出、目录权限不足、文件不存在或指标命令失败，不直接判定整台服务器离线。
- 某通道发生疑似网络错误时，上报统一协调器确认服务器状态，而不是各自启动独立重连循环。
- 逻辑状态统一不要求一次性把现有所有 SSH 连接合并成一条物理连接。

## 4. 断线检测与重连策略

### 4.1 断线检测目标

| 情况 | 建议处理方式 |
| --- | --- |
| 明确的连接关闭或网络读写错误 | 收到事件后立即同步相关状态，并判断属于通道异常还是服务器失联。 |
| 静默断网、网络黑洞 | 使用有明确响应截止时间的轻量健康探测。 |
| 正常长命令没有输出 | 不按终端输出间隔判断断线，使用独立健康信号。 |
| 应用后台、切换服务器标签 | 对仍保持会话的服务器继续统一检测，避免只监测当前面板。 |
| 电脑休眠后恢复 | 立即重新确认连接，不继续沿用休眠前绿点。 |

初始建议参数：每 10 秒一次探测，单次响应等待 5 秒，连续两次失败确认断线。第一次超时进入“连接异常待确认”，暂停新增远程操作；后续有效响应可以恢复在线。

将应用正常运行、系统未休眠情况下“约 30 秒内确认静默断线”作为待验证的验收目标，而不是当前能力或无条件硬保证。需通过可控时钟测试和真实网络故障测试核实调度方式、超时及取消机制。

仅发送 SSH keepalive 不足以保证检测时限；探测必须能确认响应，并处理响应超时。探测按服务器协调，避免每个面板重复建连或执行重型环境采集。

### 4.2 重连协调

- 每台服务器只有一个重连协调器，合并终端、SFTP、指标及按钮产生的重连请求。
- 建议自动重连最多 3 次，退避等待可从 2、5、10 秒开始调试。
- 建议自动重连周期总预算为 60 秒；总预算优先于尝试次数，耗尽即停止，不保证一定执行满 3 次。
- 单次尝试也必须有覆盖 DNS、建连、握手、认证和基础会话准备的截止时间；最终参数在实现及测试时确认。
- 手动点击重连时只允许一个在途连接，按钮显示忙碌状态，重复点击不能产生并行连接。
- 成功稳定一段时间后再重置失败预算，防止“连上即断”导致无限重试；稳定窗口通过测试确定。
- 认证失败直接进入凭据修正状态；不要把所有握手或网络错误都解释成密码错误。
- 网络中断不等于删除凭据；用户主动断开、网络失联和修改凭据必须分别处理。
- 每轮连接分配代次标识，旧连接的迟到响应不能覆盖新连接、切换后的服务器或已关闭的工作台状态。

### 4.3 连接成功的判定

不能只凭旧在线 ID、连接按钮返回或历史探测结果解除蒙板。

应在当前代次完成 SSH 身份验证并确认基础会话可用后进入在线状态；终端、SFTP 和指标继续按各自就绪状态展示。基础连接恢复不必等待完整环境采集、所有目录读取或模型服务可用。

## 5. 服务器级连接蒙板与历史查看

### 5.1 默认蒙板

蒙板覆盖当前服务器的 SFTP、终端和智能需求区域，不覆盖服务器标签导航；其他服务器和 Local 不受影响。

手动重连状态直接展示：

> 连接已中断  
> root@192.168.1.242  
> 自动重连已尝试 3 次，最近失败：连接超时  
> 重新连接 · 修改连接信息 · 查看终端历史

交互要求：

1. 点击重连后蒙板不消失，按钮切换为“正在重连”。
2. 根据真实事件展示“建立网络连接 → SSH 握手 → 身份验证 → 准备会话”。
3. 失败在原位置保留原因和操作入口，不依赖短暂的右下角提示。
4. 点击空白处不能关闭蒙板，也不能通过关闭提示绕过操作限制。
5. 只有连接成功才自动恢复正常操作；如提供停止重连按钮，停止后返回手动重连状态，保留蒙板。
6. 错误详情可以展开，但主要原因和恢复按钮必须直接可见。

### 5.2 查看历史的只读模式

提供“查看终端历史”，将大面积蒙板转换为常驻连接提示条。这是展示模式变化，不是解除连接限制。

- 保留现有终端缓冲区，可滚动、选择、复制和搜索，不允许发送按键、粘贴执行或发送命令。
- 重连过程中仍可查看历史，常驻提示条继续显示连接阶段和结果。
- 不为了展示蒙板或重建会话而销毁历史；新会话追加分隔提示，区分断线前后内容。
- SFTP 已加载目录可通过明确入口查看，标注“离线缓存／非实时”；不能把未缓存路径当作可访问目录。
- 缓存浏览不发起新的远程读取，远程上传、下载、删除、改名等操作都需要恢复连接。
- 智能任务历史和草稿保留，发送、执行及自动继续暂停。

重新建立 SSH 连接不等于恢复原远程进程，也不保证取回断线期间输出；界面不能暗示已经恢复这些内容。

## 6. 各模块行为

### 6.1 首次进入尚未连接的服务器

- SFTP：显示等待连接状态，不把旧目录显示为当前在线目录，也不把未读取成功显示成空目录。
- 终端：显示连接过程及直接可见的失败原因。
- 智能需求：显示“连接成功后可处理需求”，禁用远程任务发送；保留已有草稿和历史入口。
- 指标：显示 `—` 和“尚未连接”，不显示合成指标或上一台服务器的数据。
- 有历史缓存时仅通过明确的只读入口访问；首次从未成功连接的服务器不应出现伪造目录。

### 6.2 SFTP 缓存

- 保持按服务器隔离，增加最近成功读取时间和实时／过期标记。
- 断线时使在途目录请求失效，迟到响应不能重新标记为实时。
- 修改服务器地址、端口或身份信息时重新校验缓存归属，不能沿用原主机目录冒充新主机数据。
- 恢复连接后刷新当前路径；目录不存在或无权限时展示局部错误，不使整个工作台离线。

### 6.3 指标采集

- 指标、加载状态和最近成功时间按服务器分别存储，结果必须校验服务器及连接代次。
- 断线停止常规采集，仅保留连接恢复检测。
- 有历史数据时显示“采集已暂停 · 最后更新于……”，旧值明确标注过期。
- 没有样本时显示 `—`；未知和采集失败不能当作 0。
- 远程页面禁止回退到合成指标、本机指标或其他服务器指标。
- 恢复连接后取得新样本，才恢复“实时采集”提示。
- 智能任务只能读取对应服务器的指标，并标注采样时间和有效性；过期指标不能冒充当前观测证据。

### 6.4 凭据和错误反馈

- 连接表单直接展示认证失败，提供修改用户名、密码或连接配置的入口。
- 新凭据验证成功后再保存，不能依据历史在线 ID 判断本次认证成功。
- 验证失败不覆盖已保存的有效凭据；失败凭据不得进入自动重试循环。
- 开发者日志记录服务器标识、连接代次、阶段、耗时、重试次数及结构化错误类别。
- 用户界面给出可理解的原因，开发者详情保留排查信息；两者均不得记录密码、私钥或其他完整凭据。

### 6.5 智能需求和远程执行

- 不只禁用界面按钮，任务调度和远程操作入口也必须验证当前连接状态及代次。
- 断线后停止派发后续命令；尚未结束的模型请求即使返回计划，也不能继续触发远程执行。
- 已发送但未收到结果的命令标记为“结果待确认”，不能简单判失败或自动重跑。
- 重连后先核实远程结果，再由用户确认或按明确安全策略继续，避免重复部署、重复修改文件。
- 保留需求草稿、任务历史和证据；查看历史不要求重新连接。

## 7. 视觉与布局

沿用现有深色工作台和组件体系，不重写面板布局。科技感用于表达实际连接活动，而不是制造虚假的进度。

- 蒙层：半透明深色表面、细线连接节点、适度背景弱化，突出状态和主操作。
- 手动重连：稳定、清晰的警示状态，不持续播放让用户误以为仍在自动工作的动画。
- 正在连接：青色扫描、呼吸或节点流动效果，配合真实阶段、次数和耗时。
- 不展示虚假的百分比进度条；动效优先使用 `transform` 和 `opacity`。
- 支持减少动态效果；隐藏的面板停止无意义动画，避免多服务器同时消耗渲染资源。
- 键盘可访问重连、修改凭据和查看历史；提供明确焦点状态和状态文本。
- 服务器标签栏由目前约 48px 压缩到建议的 36–40px，具体随可点击区域和缩放测试调整。
- 标题超出使用省略号，悬停及键盘聚焦可查看完整名称；保留关闭按钮、状态点和横向溢出导航能力。

## 8. 实施拆分

| 阶段 | 内容 | 完成条件 |
| --- | --- | --- |
| P0：状态与数据正确性 | 统一服务器状态，修复残留在线记录、凭据保存判定、指标隔离及错误回退。 | 所有区域状态一致，不串服务器数据，不显示伪实时指标。 |
| P1：检测与重连协调 | 后端健康检测、总截止时间、错误分类、单服务器重连协调、代次保护。 | 可验证断线发现时限，无并行重连或无限抖动重试。 |
| P2：操作保护与交互 | 全局蒙板、首次连接状态、认证错误、只读历史、任务恢复规则。 | 未连接不能派发远程操作，历史可查看，重连期间提示持续存在。 |
| P3：视觉与紧凑布局 | 科技感动效、可访问性、服务器标签压缩。 | 不遮挡关键操作，支持缩放及减少动态效果。 |
| P4：回归验收 | 自动化状态测试、前端交互测试、实际网络故障与恢复测试。 | 下表关键场景通过，并记录真实检测和恢复耗时。 |

实施先完成状态和数据正确性，再加动效。此方案不要求迁移框架、引入新的 UI 库或重写整个工作台。

| C04 | 静默丢包／网络黑洞 | 在约定测试条件下验证约 30 秒确认目标；不得长期维持绿点。 |
| C05 | 网络短暂抖动后恢复 | 状态先待确认再恢复，保留历史，不重复执行任务或产生多组连接。 |
| C06 | 自动重连连续失败 | 次数及总预算有界，进入手动重连，所有面板显示一致。 |
| C07 | 连续快速点击手动重连 | 只有一个有效重连流程，蒙板不闪退；失败后按钮恢复可用。 |
| C08 | 连接刚成功又立即断开 | 不因每次短暂成功清零预算而无限重试。 |
| C09 | 重连期间查看终端历史 | 可滚动、复制、搜索；连接提示持续存在，不能发送终端输入。 |
| C10 | 终端正常执行 exit | 作为当前 Shell 结束处理，不误报整台服务器断线，不盲目自动重开。 |
| C11 | 长命令无输出 | 不以输出静默判定断线；健康探测正常时保持连接。 |
| C12 | SFTP 目录无权限或已删除 | 显示目录局部错误，不中断正常终端和其他通道。 |
| C13 | A 服务器请求在途时切换 B | 不显示 A 的指标或把 A 的指标带入 B 的智能任务。 |
| C14 | 修改主机或凭据后旧请求返回 | 旧代次结果不能覆盖新连接状态、目录和指标。 |
| C15 | 指标采集失败或无凭据 | 显示过期或无数据，不回退合成值、不更新时间冒充新样本。 |
| C16 | 命令已发出但断线导致结果丢失 | 标记结果待确认；恢复后先核实，不自动重复执行。 |
| C17 | 多服务器、多终端同时打开 | 每台服务器独立协调；单个通道失败不会引起全局重连风暴。 |
| C18 | 用户主动断开或关闭工作台 | 不自动重连；迟到事件不能重新置在线，相关监控按会话生命周期清理。 |
| C19 | 电脑休眠后恢复 | 立即确认连接；休眠期间不承诺固定检测时限，不沿用旧绿点。 |
| C20 | 缩放、窄窗口、键盘和减少动态效果 | 标签不溢出，关键按钮可达，状态可辨识，不依赖动画或颜色。 |

测试分层：状态转换和重试预算使用可控时钟；事件竞态与过期结果使用模拟后端；网络超时、认证和恢复使用经授权的测试服务器。不能用模拟通过替代真实网络检测能力验证。

- 每台服务器串行重连，自动尝试最多 3 次，退避 2／5／10 秒，自动恢复周期总预算 60 秒；首次主动连接单次上限 15 秒。首次连接与自动恢复周期分别计时，不把两者合称为全过程 60 秒。
- 时间预算和稳定窗口使用单调时钟；成功稳定 60 秒后重置自动重试预算，避免连接抖动导致无限重试。
- 认证失败立即停止自动重试，表单直接展示原因；只保存经过本次验证的凭据，防止并发提交不同密码时误保存。
- 加入连接代次与最新意图保护；关闭、删除或修改服务器后，旧请求不能恢复在线或覆盖新配置。
- 加入服务器工作区连接蒙板。点击空白处不会关闭，重连时持续显示；可切换为常驻只读提示条查看终端历史，不卸载终端缓冲区。
- 终端离线禁输入但保留滚动、复制和搜索。单次健康检查待确认时，不主动关闭仍健康的 Shell；正常 `exit` 不再启动自动重连。
- SFTP 首次未连接显示等待状态，离线缓存通过明确入口查看；写入、上传、下载、重试和编辑保存都验证连接状态及代次。
- 指标按服务器隔离，远程页面不再回退到合成或其他服务器指标；失联显示暂停和最后采样时间，未知显示 `—`。无有效指标时不把零值或过期样本作为模型实时上下文。

### 11.3 待实机验收及边界

1. 后端和前端均有有界健康检查，但“约 30 秒内确认静默断线”仍需实机验证，不能把模拟时钟测试视为真实网络保证。
2. 操作系统 DNS 解析使用单个有界工作队列。若系统解析器长期阻塞，调用方仍按截止时间返回，但主机名检查可能暂时失败；直接 IP 检查不依赖该队列。
3. 当前后端检查返回最终成功／失败，界面如实显示“正在验证 SSH 连接”，没有模拟握手、认证等逐阶段动画；细分真实阶段事件可后续补充。
4. 浏览器视觉验收未完成：会话中的内置浏览器返回 `No browser is available`。已有 DOM／组件交互测试，但不能代替 Tauri 桌面中的尺寸、滚动、键盘和动效检查。
5. 重新建立 SSH 连接不会恢复原远程进程，也不保证补回断线期间输出。请通过只读历史和服务器实际状态核对结果，再决定后续操作。

重启 `npm run tauri dev` 后，建议优先验证：错误密码、临时断网、自动重试耗尽、手动重连期间查看历史、恢复后的目录刷新，以及切换服务器时的指标隔离。
