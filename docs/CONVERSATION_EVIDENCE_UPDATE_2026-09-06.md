# 会话历史与证据上下文优化（2026-09-06）

## 同一会话连续展示

- 从当前任务提交独立目标或替换目标时，新任务继承 conversationId；控制台按创建时间展示同一服务器、同一会话的历史轮次、执行计划与结果。
- 会话仅用于展示。任务目标、执行证据、计划、安全约束仍按 taskId 隔离。
- 旧数据只依据“独立目标已创建新任务 / 整体目标已替换并创建新任务”审计事件中的 previousTaskId/newTaskId 恢复关联。没有关联事件的旧任务仍通过任务菜单查看，不依据时间猜测关联。
- 现有 localStorage 的任务数量、消息长度保留策略未改变；本改动不能恢复此前已经从存储中裁掉的记录。
- 按要求，在完成该部分并通过检查后，已执行 Windows 打包；后续上下文改动完成后再次打包。

## 大工具输出先存储，再按需读取

- 桌面端对超过 24,000 个 JavaScript 字符的工具证据尝试保存已脱敏的实际采集内容。原始结果已被远端工具截断时，存档仍明确 capturedPartial，不能还原从未采集的字节。
- 保存到应用数据目录 `evidence/<taskId SHA-256>/<record SHA-256>.json`。临时文件写入并同步成功后再改名；文件完整性校验成功后才返回引用。写入失败保留内联原文，不阻断任务。
- 证据包含目标、采集时间、原证据 ID、步骤 ID、截断标记；任务和证据 ID 均不能作为任意路径使用。
- 模型在可调用 evidence.read 的阶段收到短预览及引用。禁用或禁止读取工具时，正常快照使用原文；不支持调用工具的兼容评审也保留原文。
- `evidence.read` 仅由编排器绑定当前 taskId，模型不能传入其他任务 ID。offset 按 Unicode 字符计数，默认 6,000、最多 12,000 字符一页；nextOffset 用于后续页。
- 原始执行账本不被预览替换，压缩后的证据摘要保留 archive 引用。读取存档不是远端重新验收。读取结果页不会再次存档形成递归引用。
- 当前自动存档覆盖注册工具输出，尚未覆盖所有 Shell 输出；没有新增 LLM 摘要调用或长期记忆写入。

## 业务判断与诊断

- 证据去重比较原始文本相等，不再把“裁剪后预览相等”当作原文相等。
- 滚动摘要保留全部未解决问题。相同命令只有在相同 attemptContext 中存在关联成功证据且观测匹配时才自动清除问题；跨服务器、会话、凭据版本的成功不会自动消除旧问题。缺少身份的旧问题保守保留。
- 请求日志及索引记录 contextMetrics：消息字符数/UTF-8 字节数、整个请求体积、稳定前缀指纹及长度。estimatedInputTokens 是字节数除以 3 的粗估，显式标注 exactTokens=false，不是供应商计费 Token。
- 未配置模型窗口时不猜测“达到 90%”的压缩阈值，也不会因此截断用户目标、规则或验收要求。实际用量、缓存命中应结合供应商 response.usage 核对。

## 验证与边界

覆盖连续 Java/MySQL 消息展示、旧任务关联、跨服务器隔离、存储失败回退、按需预览、禁用召回时原文回退、分页参数、任务隔离、Unicode 分页、内容完整性、未解决问题超过 8 条及跨目标成功的测试。

验证结果：`npm run check` 通过；Vitest 89 个文件、635 项通过、16 项跳过；日志分析 Node 测试通过。Rust 全量运行 98 项通过、2 项忽略，1 项因本机缺少 bash 失败；单独排除该已知环境测试后其余全部通过。

尚未实现全量任务数据库迁移、自动语义摘要、模型窗口压力控制及分类后重建新任务规划请求。当前改动不宣称这些能力已经完成，也不把短预览的字符下降当作实际任务 Token 节省比例。
