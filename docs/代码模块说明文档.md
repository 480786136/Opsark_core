## 1. 总体调用关系

```text
Vue 页面和组件
  -> Pinia 领域状态 + src/stores/ops.ts 用例编排
    -> Agent 纯规则: src/features/agent/
    -> 工具注册与执行: src/features/tools/
    -> 后端适配: src/services/backend.ts
      -> 浏览器演示实现
      -> Tauri commands
        -> SSH / SFTP / 模型 / 系统钥匙串
```

基本原则：

- 页面只处理展示和用户交互，不直接调用 Tauri。
- Pinia 保存应用状态并协调一次完整用例。
- 可测试的业务规则放在 `src/features/`。
- `backend.ts` 屏蔽浏览器演示模式和 Tauri 运行模式差异。
- Rust command 负责真实 SSH、SFTP、凭据和模型网络请求。

## 2. 前端入口与页面

### `src/main.ts`

创建 Vue 应用，注册 Pinia 和 Vue Router，并加载全局样式。

### `src/router.ts`

定义以下页面路由：

- `/`：服务器总览。
- `/server/:id`：服务器工作台。
- `/logs`：审计日志。
- `/settings`：模型、安全信息和工具管理。

页面使用动态 `import()` 按路由加载。Xterm 只随服务器工作台进入独立分包，不进入首屏代码。

### `src/App.vue`

应用壳层和主导航。页面业务状态不应放入此组件。

### `src/views/SettingsView.vue`

设置页容器，负责：

- 大模型配置。
- 模型输出限制。
- 引入 `ToolManagementPanel`。
- 敏感变量管理。
- 统一触发模型、工具和敏感配置保存。

### `src/views/LogsView.vue`

审计日志检索和详情展开。当前支持 `task`、`model`、`tool`、`command` 和 `system` 五类事件。

### `src/views/WorkspaceView.vue`

服务器操作工作台，组合 SFTP 文件区、Linux 终端、智能任务控制台和实时指标。页面读取布局状态生成 CSS 网格变量，处理分隔线指针拖拽和方向键微调；比例约束与持久化规则不放在页面中。

头部使用服务器窗口标签栏展示所有已打开服务器，新增按钮负责打开其他服务器窗口。路由参数变化使用激活代次重新检查目标连接并刷新指标，旧异步结果不能覆盖新服务器。关闭活动窗口后按视觉顺序激活相邻窗口。

所有打开服务器的 `TerminalWorkspace` 和 `AgentConsole` 同时挂载，标签切换只使用 `v-show` 隐藏后台窗口，不卸载 Xterm、关闭 PTY 或销毁智能需求控制台。SFTP 与 AI 面板跟随活动服务器显示；终端布局、SFTP 路径、活动任务和 AI 输入状态均按服务器隔离。`WorkspaceView` 由路由 `KeepAlive` 缓存，离开工作台页面不会中断已打开终端。工作台级激活标记保证后台输出只进入对应 Xterm，不进入当前模型上下文。

### Shell 工作台新模块

#### `src/components/TerminalPanel.vue`

使用 Xterm.js 承载单个真实 PTY，不再使用文本列表模拟终端。负责加载尺寸适配、搜索和链接插件，同步远程 PTY 行列，并提供重连、Ctrl+C、选区复制、清屏、粘贴确认和会话历史。连接标题由 `TerminalWorkspace` 放在选项卡中，低频操作收进右上角菜单。组件通过 `statusChange` 上报稳定连接状态；标签关闭后由父级卸载，卸载流程会释放 Xterm、监听器、计时器并关闭对应后端 PTY。

安全边界：原始 PTY 数据只写入 Xterm 以保留 ANSI 控制；供模型使用的终端上下文由 `terminalTranscript.ts` 去除 ANSI 并限制最大行数。

终端根据后端结构化状态事件展示连接、断开和错误状态。可重试断线使用 1/2/4 秒指数退避；认证失败和主动关闭不自动重试。

所有 Xterm `onData` 输入先经过 `writeTerminalInput()`。多行、bracketed paste 或高风险粘贴会停在前端确认层，确认前不会调用 `backend.writeTerminal()`。字号、行高和终端配色变化会更新当前 Xterm options，并重新执行 FitAddon 与远端 PTY resize。

终端只在“已连接、当前标签活动且未被智能任务锁定”时消费 SFTP 路径请求，使用经过 POSIX 单引号转义的 `cd --` 命令切换目录。终端输出中的标准 OSC 7 标记会更新当前终端目录；用户点击同步按钮后，该目录通过工作台联动 store 交给同一服务器的 SFTP。

组件根据 `agentTaskId` 消费本终端的 Agent 输出队列，并在同一面板切换为只读输出视图，展示需求理解、计划、审批、命令、脱敏流式输出、退出状态、独立校验和总结。输出限制为最近 120,000 个字符，任务结束后可通过右上角菜单在 Agent 输出和 Shell 间切换；刷新后可从持久化任务事件重建最近输出。

智能需求执行使用独立 SSH 命令通道，其外部输出不会写入交互式 PTY，避免远端 Shell 光标状态与本地 Xterm 显示失步。任务处于 `planning`、`running` 或 `validating` 时，组件拒绝键盘写入、快捷键输入、目录请求和 Xterm 聚焦；锁定只作用于任务绑定终端。

#### `src/features/terminal/terminalInput.ts`

终端输入安全与会话历史纯规则模块，负责：

- 规范化 bracketed paste 预览，计算行数并识别删除、关机、格式化磁盘、管道执行脚本和破坏性 SQL 等高风险命令。
- 只识别以 `$`、`#`、`%` 结束的常见 Shell 提示符；不确定时不采集历史。
- 跟踪普通字符、退格、清行、终止和回车，提取用户提交的命令。
- 排除密码参数、Token、Secret、API Key 赋值等敏感命令，限制当前会话最多 100 条历史。
- 解析系统风格和 VS Code 风格的搜索、复制、清屏及历史快捷键。

命令历史只保存在各 `TerminalPanel` 组件内存，不进入 Pinia、localStorage、审计日志或模型上下文。应用重启和标签关闭都会清空历史。

#### `src/features/terminal/TerminalWorkspace.vue`

单服务器终端标签容器。每个标签对应一个真实 PTY，标题格式为 `Shell · 用户@主机 · 序号`，右侧 `X` 直接关闭该终端；关闭活动标签后选择相邻项，最后一个标签关闭后展示空工作区和新建按钮。标签栏支持水平滚动，并使用主题令牌美化滚动条。

所有已打开标签同时挂载，切换时仅通过 `v-show` 控制可见性，因此当前运行期的 PTY、远端前台进程和 Xterm 滚屏记录不会因切换而销毁。绑定任务的标签显示 Bot 图标，执行中显示动态状态；组件将 `agentTaskId` 传给对应的 `TerminalPanel`，不会把任务输出路由到后来切换的标签。

#### `src/features/terminal/terminalSessionStore.ts`

保存每台服务器的终端标签顺序、活动标签、PTY 标识、连接状态和任务绑定，每台服务器最多 8 个标签。`bindAgentTask()` 将任务绑定到提交时的活动标签，并持久化该终端的 `agentTaskId`；`resolveTaskPaneId()` 为后续流式事件提供稳定目标，切换标签或服务器不会改变路由。

Agent 输出队列只接受已绑定任务的目标终端，最多保留 500 个分块；输出消费、标签关闭或工作区清理后立即释放。输出正文不写入布局 localStorage，刷新后的展示由持久化任务事件重建。

持久化键仍为 `opsark.terminalWorkspaces.v2`。读取历史分屏数据时，将布局树中的 Shell 叶子按视觉顺序展开为独立标签，保留可用 PTY 标识和原活动叶子；旧 Agent 叶子被丢弃。应用只恢复布局元数据并创建新 PTY，不伪造远程进程恢复状态。

#### `src/features/terminal/terminalSplitTree.ts`

旧二叉分屏布局的兼容纯规则模块。运行时不再创建、调整或拖放分屏；当前仅在读取历史持久化数据和迁移测试时用于：

- 收集稳定的视觉叶子顺序。
- 将旧平铺布局迁移为保持顺序和比例的树。
- 在目标叶子创建指定方向的新分支。
- 删除叶子并提升兄弟节点，实现父分支归并。
- 更新指定分支比例并限制在 15%-85%。
- 交换相邻叶子引用，实现不重建 PTY 的位置移动。
- 将源叶子移动到目标叶子的左、右、上、下边缘；源分支先归并，目标位置再创建 50% 局部分支，源叶子节点 ID 保持不变。

#### `src/features/terminal/terminalPaneLayout.ts`

旧平铺分屏比例的兼容纯规则模块，负责：

- 生成总和严格为 100% 的等比分配。
- 归一化不可信持久化比例，并拒绝低于 15% 的分屏。

该模块只用于 v1 数据归一化和迁移测试；旧运行期调整接口已删除，当前运行时布局为独立终端标签。

#### `src/features/terminal/terminalTranscript.ts`

处理跨 PTY 数据块的残留行、换行归一化和转录裁剪。该模块是纯函数边界，已覆盖 ANSI、分块和最大行数测试。

#### `src/features/terminal/terminalReconnect.ts`

定义最多三次重连、1/2/4 秒退避和会话代次过滤规则。终端代次来自 Rust `TerminalManager`，旧会话延迟事件不能覆盖新会话状态。

#### `src/components/FileExplorer.vue`

SFTP 文件工作区，提供路径面包屑、列表/紧凑视图、排序、多选、键盘导航、右键菜单、上传、下载、创建、重命名和删除。文件名冲突支持跳过、覆盖和换名上传，不依赖浏览器 `prompt/confirm`。

目录导航通过 `loadDirectory()` 统一处理。组件读取当前服务器的文件工作区快照；加载成功后才清空选择，加载失败时保留当前路径、文件列表和选择，按权限不足、断线、目录不存在或未知错误显示状态，并允许重试。过期响应不触发界面错误。创建、重命名和删除只消费统一变更结果，并在 i18n 边界将审计标题键转换为最终日志文案。

工具栏可将当前目录发送到同一服务器的活动终端。组件监听终端产生的 SFTP 路径请求，目录加载成功后按请求 ID 消费；失败请求保留，避免连接恢复前丢失用户操作。

#### `src/features/files/fileWorkspaceStore.ts`

保存文件视图偏好和按服务器隔离的运行期目录状态：

- `viewMode` 只允许 `list` 或 `compact`，使用 `opsark.fileWorkspace.v1` 持久化。
- `serverWorkspaces` 按服务器保存文件列表、当前路径、加载状态、请求代次、最后成功路径和目录错误。
- 目录文件快照只保存在内存；每台服务器最后成功路径写入 `opsark.fileWorkspace.v1`，重新进入窗口时使用真实 SFTP 重新加载，不恢复过期文件列表。
- `loadDirectory()` 只允许当前请求代次更新状态，解决快速导航时旧响应晚返回造成的目录回跳。
- `createDirectory()`、`renameEntry()` 和 `deleteEntry()` 执行远程变更后刷新当前服务器目录，并返回统一 `FileMutationResult`，不经过通用 store。
- `classifyDirectoryLoadError()` 将后端文本异常收敛为稳定错误码，组件只依赖错误码选择双语文案。

#### `src/features/files/fileMutationResult.ts`

SFTP 变更结果和审计 DTO 边界：

- `FileMutationResult` 绑定操作类型、源/目标路径、目录刷新结果和审计信息，避免一次变更被组件拆成多个不一致状态。
- `FileMutationAuditDto` 保存稳定的 i18n 标题键、日志等级、详情和服务器范围，不直接保存中文界面标题。
- `localizeFileMutationAudit()` 只在界面边界生成最终 `AuditEvent`，删除操作保留警告等级。

#### `src/features/files/remotePath.ts`

集中处理 POSIX 远程路径规范化、拼接、父目录、面包屑和文件名校验。函数返回稳定错误码，界面层负责翻译。

#### `src/features/files/fileWorkspace.ts`

实现文件排序、多选、Shift 连续区间和键盘上下移动等纯规则。排序时始终保持目录优先，文件大小使用字节值而非字符串比较。

#### `src/features/files/transferQueueStore.ts`

串行编排上传和下载任务，根据后端实际字节事件计算进度、速度和剩余时间，并管理取消、重试和清理。连接密码和文件字节保存在模块内存 `Map`，不进入 Pinia state 或 localStorage。

#### `src/features/files/TransferQueuePanel.vue`

展示当前服务器的传输队列、进度条、速度、剩余时间以及取消/重试操作。

#### `src/features/files/fileEditor.ts`

纯函数文本协议模块，负责识别 UTF-8、BOM 和 LF/CRLF/CR/Mixed 换行，并按用户选择重新编码。二进制、非法 UTF-8 和超过 2 MB 的文件会返回明确错误码。

#### `src/features/files/FileEditorPanel.vue`

远程文本编辑工具，提供编码/换行元数据、保存状态、`Ctrl/Cmd+S` 保存和未保存关闭确认。只在成功保存后写入审计日志。

#### `src/features/preferences/`

- `i18n.ts`：中文和英文语言资源，覆盖导航、服务器、设置、工具管理、日志、工作台、终端、SFTP、Agent、状态、指标和外观控件。界面日期格式读取当前 locale；模型与命令产生的证据不做前端翻译。
- `preferenceStore.ts`：语言、界面主题、强调色、终端配色、字号、行高和快捷键预设，使用 `opsark.preferences.v1` 持久化，在 Vue 挂载前应用。界面主题包括炭黑、墨夜、石墨、瓷白和晨雾；枚举与数值均经过白名单或上下界校验。
- `AppearanceControls.vue`：侧边栏语言、五套界面主题、六种强调色、三套终端配色、排版滑块和快捷键预设控制。亮色界面使用高对比强调色覆盖，终端画布继续读取独立终端主题令牌。

`i18n.test.ts` 递归比较中英文叶子键，拒绝缺失或空资源，并验证运行时切换立即生效。新增界面文案时必须同时补齐两种语言，不能依赖回退语言掩盖缺失键。

#### `src/features/workspace/workspaceLayoutStore.ts`

工作台布局状态与纯规则模块，负责：

- 定义终端优先、均衡、文件优先和 AI 优先四种稳定布局预设。
- 调整分隔线两侧比例，并保证文件不低于 12%、终端不低于 30%、AI 不低于 24%。
- 使用 `opsark.workspaceLayout.v1` 保存自定义比例和最近预设。
- 管理单面板专注状态。专注状态是当前会话交互，不写入本地存储，避免重启后隐藏其他面板。

`resizeWorkspaceColumns()` 是无 DOM 依赖的纯函数。视图拖拽期间只更新内存状态，在指针释放时统一持久化，避免高频写入 localStorage。

#### `src/features/workspace/WorkspaceToolbar.vue`

工作台布局控制器，提供布局预设菜单和文件、终端、AI 专注按钮。桌面端使用紧凑图标分段控件；窄屏隐藏分段控件，但在布局菜单中保留相同专注操作，确保终端和文件面板仍可访问。所有可见文案和辅助功能标签均来自 i18n。

#### `src/features/workspace/serverWorkspaceTabsStore.ts`

服务器窗口标签持久化模块：

- 使用 `opsark.serverWorkspaceTabs.v1` 保存窗口顺序、打开服务器 ID 和活动服务器 ID，不保存连接密码或终端输出。
- 恢复时按当前服务器清单过滤已删除 ID，并限制最多 12 个同时打开窗口。
- `open()`、`activate()` 和 `close()` 每次变更立即持久化；关闭活动窗口时返回视觉相邻窗口供路由替换。
- 该 store 只描述窗口记录；运行中的 Xterm 和 PTY 生命周期由 `WorkspaceView` 的常驻终端容器拥有。

#### `src/features/workspace/workspaceLinkStore.ts`

终端与 SFTP 的瞬时路径协议模块：

- 按服务器保存待消费的终端路径和 SFTP 路径请求，使用递增请求 ID 防止旧完成结果删除新请求。
- 按分屏保存最近一次 OSC 7 工作目录；分屏卸载时清理，不进入 localStorage。
- `quoteShellPath()` 使用 POSIX 单引号规则生成不可插值路径参数。
- `extractOsc7Directories()` 只接受 BEL 或 ST 正常结束的 `OSC 7;file://` 标记，并规范化 URI 路径；普通 `pwd` 文本不会触发导航。

传输队列、文件视图、目录列表、加载标记、恢复状态和目录变更编排均已脱离 `ops.ts`。文件组件从通用 store 读取当前运行期连接，并将连接交给文件工作区用例；创建、重命名和删除已使用统一审计 DTO，上传、下载、文本保存和目录读取日志仍待迁移到相同边界。

## 3. 工具系统

工具系统是设置页、模型上下文和执行器之间的唯一工具信息来源。

### `src/features/tools/types.ts`

核心类型：

- `ToolDefinition`：完整工具定义。
- `ToolOverride`：允许持久化的用户覆盖字段。
- `ToolCall` / `ToolResult`：统一调用和返回协议。
- `FileStructureRequest` / `FileStructureResult`：文件结构工具协议。

安全字段 `implementation`、`inputSchema`、`builtIn` 和 `version` 始终来自代码目录，不能被本地覆盖配置替换。

### `src/features/tools/toolCatalog.ts`

内置工具的唯一默认目录。目前包含：

| ID | 内部执行器 | 用途 |
|---|---|---|
| `server.basic_info` | `serverBasicInfo` | 获取服务器基础信息和软件环境 |
| `server.realtime_metrics` | `serverRealtimeMetrics` | 获取实时资源指标 |
| `secret.metadata` | `secretMetadata` | 管理敏感变量元数据 |
| `secret.merge_command` | `secretMergeCommand` | 执行期合并敏感占位符 |
| `user.request_input` | `userRequestInput` | 请求用户补充输入 |
| `files.get_structure` | `getRemoteFileStructure` | 获取远端目录树 |

修改默认名称、说明、输入 schema 或版本时，应同时更新工具测试和本说明文档。

### `src/features/tools/toolRegistry.ts`

负责：

- 解析不可信的 localStorage 数据。
- 将默认目录与用户覆盖合并。
- 只生成可编辑字段的持久化覆盖。
- 恢复单个工具默认值。

持久化键：`opsark.toolOverrides`。

### `src/features/tools/toolValidation.ts`

校验并清理工具可编辑字段：

- 名称最多 80 字符。
- 工具说明最多 1000 字符。
- 模型使用规则最多 2000 字符。
- 返回说明最多 1000 字符。
- 所有字段必须为非空文本，保存前执行 `trim()`。

### `src/features/tools/toolContext.ts`

生成模型可见工具快照，只包含已启用工具的：

- ID、名称和说明。
- 模型使用规则。
- 输入 schema 和返回说明。
- 工具版本。

内部执行器名称和 UI 状态不会进入模型上下文。输入 schema 使用 JSON 快照，因为 Pinia 响应式代理不能直接传给 `structuredClone()`。

### `src/features/tools/toolExecutor.ts`

统一工具调用路由。执行顺序：

1. 检查工具是否存在。
2. 检查工具是否启用。
3. 校验调用参数类型。
4. 根据可信 `implementation` 路由到实际依赖。
5. 返回稳定的 `ToolResult` 和错误 code。

当前可由统一路由直接调用的外部工具是 `files.get_structure`；其他工具仍由现有内部任务流程调用。

模型在计划步骤中使用以下受控命令协议：

```text
opsark-tool files.get_structure {"rootPath":"/opt/app","excludeDirectories":[]}
```

`runStep()` 会在发送 SSH 命令前识别该协议并交给工具执行器，因此 `opsark-tool` 不会进入远端 shell。工具结果作为结构化步骤证据保存，发现计划结束后会进入证据驱动的继续规划；后续模型上下文同时包含目录证据和当前启用工具清单。

### `src/features/tools/fileStructure.ts`

负责文件结构请求的前端参数规范化和浏览器演示结果：

- 根路径必须为绝对路径。
- 排除项不能是绝对路径或包含 `..`。
- 默认深度 6，允许 1 到 20。
- 默认节点数 2000，允许 1 到 10000。
- 合并默认排除目录并去重。
- 演示模式同样实现排除、隐藏文件、深度和节点限制。

### `src/features/settings/ToolManagementPanel.vue`

工具管理界面，提供搜索、选择、启停、编辑、校验、只读查看 schema 和恢复默认。组件直接编辑 Pinia 中的工具草稿，最终由设置页统一调用 `store.saveTools()` 校验和持久化。

## 4. Agent 领域模块

### `src/components/AgentConsole.vue`

智能需求处理控制台。每个已打开的服务器窗口拥有独立实例，并从 `agentWorkspaceStore` 读取当前服务器的活动任务、需求草稿、授权模式、模型、自动化开关和任务列表展开状态。

提交新需求时，组件先确定当前服务器的任务，再将任务 ID 显式传给 `ops.submitRequirement()`，避免依赖全局活动任务产生跨服务器串写。删除任务后只校正所属服务器的选择状态；恢复自动化模式时会重新检查当前模型是否可用。

安全边界：终端引用和敏感信息输入只保存在组件内存中，不写入 localStorage。所有服务器控制台在工作台运行期常驻挂载，因此服务器标签切换后仍保留滚动位置和局部交互状态。

### `src/features/agent/agentWorkspaceStore.ts`

按服务器保存智能需求处理工作区状态，持久化键为 `opsark.agentWorkspaces.v1`。模块负责：

- 校验并恢复活动任务 ID、草稿、授权模式、模型、自动化开关和任务列表展开状态。
- 使用短延迟合并连续写入，并限制草稿持久化长度。
- 在任务删除或恢复后校正活动任务，且只处理对应服务器的任务集合。
- 在服务器删除时清理该服务器工作区记录。

该 store 不保存任务消息、执行步骤或审计记录；这些业务数据继续由 `opsark.tasks` 管理。

### `src/features/agent/agentService.ts`

Agent 异步用例层，当前已接管：

- `planDiscoveryContinuation()`：使用已完成发现证据构建上下文，调用模型生成剩余变更和验收步骤。
- 续规划返回前去除已有命令、空命令和同批次重复命令；无新步骤时显式失败。
- `summarizeTaskExecution()`：使用最新需求和实际步骤生成完成总结。
- `planTaskAdjustment()`：使用失败证据生成替代计划，仅保留最近 4 个已完成步骤，并拒绝空调整计划。
- `summarizeFailedTask()`：组合确定性失败原因和可选的模型执行总结。
- 仅在实际调用远程模型时输出总结请求审计快照。

模型计划与总结函数都可以通过参数注入，单元测试不依赖 Pinia、Tauri 或真实模型。

### `src/features/agent/modelRuntime.ts`

统一将模型配置、API Key、上下文和生成限制转换为后端 `RuntimeModel`。缺少模型或凭据时返回 `undefined`，调用方据此进入内置或规则回退路径。

### `src/features/agent/reviewService.ts`

Agent 异常复查用例层，负责：

- `reviewPrecondition()`：复查变更前的未解决阻断；仅真实模型明确返回 `continue` 时允许继续。
- `reviewExecutionFailure()`：复查主命令失败，并禁止非诊断失败被模型改写为完成。
- 主命令失败后只有诊断结果或剩余计划中的明确恢复步骤可以允许继续。
- `reviewExecutionEvidence()`：复查后置校验失败或证据冲突，并应用确定性硬阻断、剩余修复计划和连续只读诊断规则。
- 同时返回 `modelDecision` 和 `finalDecision`，审计可以追溯程序门禁对模型决策的修正。

复查函数支持参数注入，不直接访问 Pinia、Tauri 或真实模型凭据存储。

### `src/features/agent/agentContext.ts`

构建首次需求规划上下文，包括：

- 服务器基本信息和软件环境。
- 实时指标和授权等级。
- 终端引用、历史对话和上一轮执行。
- 已知执行事实。
- 已启用工具的模型安全快照。
- 当前服务器可用的敏感变量元数据和占位符。

真实敏感值不属于该函数的输入，因此不会被意外序列化到模型上下文。

该模块还统一负责：

- `trimEvidence()`：按模型上下文预算裁剪命令证据。
- `extractKnownExecutionFacts()`：从已完成步骤提取仓库 URL 和可信工作目录。
- `buildAdjustmentContext()`：失败调整上下文。
- `buildContinuationContext()`：发现完成后的续规划上下文。

三类模型上下文共享服务器快照、工具快照和敏感变量元数据映射规则。

### `src/features/agent/approvalPolicy.ts`

统一步骤审批规则：

- `observe`：所有步骤确认。
- `safe`：低风险自动，中高风险确认。
- `managed`：自动批准计划，低中风险自动，高风险确认。
- 明确破坏性命令始终确认，不受授权等级影响。
- 历史 `autonomous` 配置统一迁移到 `safe`。

### `src/features/agent/stepApproval.ts`

步骤审批协调模块，负责：

- 复用 `approvalPolicy.ts` 判断当前授权等级和命令是否要求审批。
- 通过 `stepMachine.ts` 将待执行步骤置为 `awaiting_approval`。
- 生成稳定的中文风险提示，并仅接受当前确实等待审批的步骤。

批准后步骤仍由执行分派决定进入运行或敏感输入等待，模块不会提前伪造运行状态。

### `src/features/agent/secretTool.ts`

负责：

- 查找 `${secret.KEY}` 占位符。
- 在执行期合并真实值。
- 对终端、日志和模型复核输出进行脱敏。

本模块不负责持久化真实值。真实值仍由 store 调用系统钥匙串后端保存。

### `src/features/agent/planNormalizer.ts`

负责：

- 修复被模型错误转义的敏感占位符。
- 在用户未要求清理时移除推测性删除步骤。
- 为每个计划步骤补充标准校验器。

`src/services/backend.ts` 继续重新导出这些函数，以保持现有调用方兼容。

### `src/features/agent/executionSummary.ts`

根据真实步骤状态、结构化结果和输出构建规则兜底总结。模型总结不可用时由 `backend.generateSummary()` 使用该结果。

### `src/features/agent/executionRunner.ts`

封装单步主命令和独立 validation 的执行边界：调用后端执行器、清洗终端控制字符、对流式和最终输出统一脱敏。取消、步骤状态和 UI 时间线由用例协调层管理。

### `src/features/agent/executionLifecycle.ts`

远程命令和独立校验的生命周期协调模块，负责：

- 在命令开始时登记执行 ID，并在成功、失败或抛出异常时通过 `finally` 停止监控和清理 ID。
- 累计已脱敏的流式输出，并把单个数据块和累计输出交给 UI 回调。
- 接收长任务监控心跳、事件、审计和错误回调，不直接访问 Pinia。
- 当定期校验确认目标已满足时，将停止等待产生的退出码 130 规范化为可进入正式校验的成功结果。
- 对失败的只读 HTTP 独立校验自动重试一次，并分别管理两次校验执行 ID。

命令执行器、校验执行器和监控器均支持依赖注入，测试不需要真实 SSH 或定时器。

### `src/features/agent/executionPreparation.ts`

步骤执行准备模块，负责：

- 规范化模型可能错误转义的`${secret.KEY}`占位符。
- 同时返回可安全展示/审计的命令模板，以及仅传入执行器的敏感值解析结果。
- 仅在服务器资料与密码同时存在时创建SSH连接参数。
- 通过`modelRuntime.ts`统一创建可选模型运行参数。

本模块返回的`resolvedCommand`和`resolvedValidation`不得写入日志、消息或持久化状态。

### `src/features/agent/executionAudit.ts`

命令与程序证据审计投影模块，负责：

- 使用占位符命令模板和已脱敏输出构建主命令结果事件。
- 使用模板校验命令、规范化校验器和`StepResult`构建程序证据校验事件。
- 根据执行结果、证据接受状态和观察状态统一计算日志等级。
- 不接受SSH密码、模型API Key或敏感变量映射作为输入。

### `src/features/agent/validationOutput.ts`

独立校验输出组装模块，负责：

- 按执行顺序追加首次失败校验和最终校验输出，并使用稳定的分隔标题。
- 将缺失输出规范化为空字符串，避免在步骤输出中出现`undefined`。
- 主命令输出为空时省略前导空行，保持持久化输出可直接阅读。

该模块只处理已脱敏文本；终端行数限制仍由`terminalBuffer.ts`负责。

### `src/features/agent/terminalBuffer.ts`

终端输出缓冲模块，负责：

- 将连续的百分比进度帧更新为最新值，而不是持续追加重复行。
- 区分流式与非流式命令完成输出，避免重复命令提示符或完整输出。
- 统一追加命令、校验和手动终端输出块。
- 对所有入口应用相同的 2000 行容量限制。

函数直接维护传入数组以保持 Pinia 响应式对象身份，但不访问任何 store。

### `src/features/agent/executionDispatch.ts`

步骤执行前的纯分派模块，统一返回：

- `tool`：命令符合模型工具协议，并携带已校验的 `ToolCall`。
- `await-secret`：普通命令仍缺少本轮确认的敏感变量。
- `command`：可以进入远程命令执行。
- `invalid`：工具协议无效，返回稳定错误信息而不向外抛出解析异常。

该模块不修改步骤或任务，便于后续执行协调器直接消费分派结果。

### `src/features/agent/stepExecutionEntry.ts`

步骤执行入口协调模块，负责：

- 消费工具、协议错误、敏感输入和远程命令四类分派结果。
- 将协议错误和敏感输入等待交给中断模块写回步骤。
- 初始化远程命令的开始时间、运行状态和进度文案。
- 返回任务目标状态、暂停原因、事件消息和终端标题，由 store 分发副作用。
- 将未预期执行异常转换为稳定的步骤失败与任务暂停协调结果。

### `src/features/agent/toolStepResult.ts`

工具步骤结果纯函数模块，负责：

- 将工具调用成功、结果截断和调用失败转换为统一的 `StepResult`。
- 为成功结果生成结构化执行证据和规则复核结论。
- 生成进度文案、时间线事件和失败暂停原因。
- 通过 `applyToolStepOutcome()` 写回既有步骤对象，但不访问 Pinia、后端或模型。

### `src/features/agent/toolStepLifecycle.ts`

工具步骤生命周期模块，负责：

- 通过步骤状态机开始工具调用并记录开始时间。
- 捕获执行边界异常，将其转换为 `TOOL_EXECUTION_FAILED` 结构化失败。
- 计算工具执行耗时并应用 `toolStepResult.ts` 生成的结果。
- 在异步结果返回后先检查取消状态，禁止覆盖用户终止写入的结果。
- 返回任务目标状态、暂停原因、事件消息和是否继续推进。

实际工具调用、日志落库、任务状态提交和后续步骤调度仍由 store 负责。

### `src/features/agent/commandStepResult.ts`

主命令步骤结果纯函数模块，负责：

- 构建长任务被定期复查中止时的失败结果和执行证据。
- 分类主命令失败原因，并保证结果事实与证据事实一致。
- 通过步骤状态机一次性写回主命令失败状态、结果和证据。
- 将程序校验分类结果和规范化校验器写回既有步骤。
- 统一维护 `StepResult.evidenceIds`，避免 store 手工拼接后出现引用不一致。

### `src/features/agent/stepInterruption.ts`

步骤中断和等待写回模块，负责：

- 取消活动步骤，并保留已收集证据的 ID。
- 将工具协议解析失败和未预期执行异常写为稳定失败分类。
- 将步骤置为敏感输入等待，并在确认后恢复到执行队列。
- 同步维护状态、进度文案和结构化结果，避免 store 分散赋值。

### `src/features/agent/reviewCoordination.ts`

复查决策写回模块，负责：

- 将主命令失败后的 `adjust`、`continue` 和 `complete` 决策转换为任务目标状态和时间线消息。
- 将前置条件复查结论写回当前步骤，并返回是否允许执行当前步骤。
- 将长任务定期复查的调整结论一次性写回步骤状态、复查、结果和证据，并生成任务暂停信息。
- 将执行证据复查决策转换为步骤完成/失败状态。
- 在整体目标完成时统一跳过剩余步骤。
- 返回 `shouldAdvance`，由 store 决定是否继续任务推进和持久化。

### `src/features/agent/reviewAudit.ts`

复查审计投影模块，负责：

- 构建前置条件复查、长任务定期复查和主命令失败复查事件。
- 将执行证据复查转换为有序的模型事件、后置条件最终决策和阻断门禁事件。
- 同时保留模型原始决策与规则最终决策，便于追踪安全门禁修正。
- 统一事件等级、标题和JSON字段，不访问store或持久化层。

### `src/features/agent/stepReviewPipeline.ts`

步骤复查用例pipeline，负责组合：

- 前置条件、主命令失败和执行证据三类异步复查。
- `reviewAudit.ts`的审计投影。
- `reviewCoordination.ts`的步骤、剩余计划和任务目标状态协调。

pipeline接收`isCancelled()`回调。异步复查结束后如果任务已取消，将返回`cancelled`且不应用任何审计或状态修改。

### `src/features/agent/longRunningMonitor.ts`

长命令运行期监控器，负责：

- 每秒更新运行时长和进度文案。
- 长时间运行时向任务时间线发送提示。
- 有真实连接和可用模型时，每 30 秒执行一次脱敏后的独立校验与模型复查。
- 防止复查重入，并在命令结束时统一清理定时器。
- 仅接受真实模型决策；缺少独立通过证据时不接受 `complete`。

模块通过回调输出进度、消息、审计和错误，不直接访问 Pinia 状态。监控器的创建、停止和命令执行清理由 `executionLifecycle.ts` 统一协调。

### `src/features/agent/evidenceReview.ts`

Agent 领域的确定性证据复查入口，负责：

- 导出步骤结果分类器和校验器推断。
- 区分只读诊断和用户明确请求的变更。
- 判断剩余计划是否包含恢复或后置条件修复步骤。
- 识别校验命令不存在、平台不兼容、网络失败等模型不可覆盖的硬阻断。

### `src/features/agent/reviewContext.ts`

集中构建四类模型复查输入：前置条件阻断、长任务定期复查、主命令失败和后置条件/证据异常。公共快照函数保证完整计划、历史步骤、剩余步骤和原始证据使用一致字段和裁剪规则。

### `src/features/agent/auditTrail.ts`

统一创建和保留审计事件：导出`AuditEventDraft`、清理标题和详情、分配ID/时间，并只保留最新500条。store的`addLog()`已改为调用该模块；以后切换SQLite时可在存储边界继续演进。

### `src/features/agent/taskMachine.ts`

集中定义任务合法状态迁移并同步更新时间。当前已覆盖首次规划、计划审批、发现续规划、步骤审批、敏感输入、执行校验、暂停调整、完成、失败和取消。

`ops.ts` 中所有任务状态更改都已经调用 `transitionTask()`；非法迁移会显式抛错，合法迁移会同步更新 `updatedAt`。

### `src/features/agent/stepMachine.ts`

集中定义步骤合法状态迁移，覆盖待执行、等待审批、等待敏感输入、运行、校验、完成、失败和跳过。

`ops.ts` 中所有生产步骤状态更改都已经调用 `transitionStep()`。已完成、失败和跳过为终态，不能被静默放回执行队列；重复写入相同状态仍保持幂等。高风险步骤批准后允许进入敏感输入等待，确认变量后再回到待执行状态。

### `src/features/agent/taskProgression.ts`

任务推进纯规则模块，负责：

- 提取最新用户需求，不把“重试”等用户事件误当为需求。
- 选择下一个待执行步骤。
- 判断已完成的只读发现计划是否需要一次续规划。
- 去除续规划中已执行或重复的命令。
- 在变更前查找尚未被成功修复步骤清除的阻断证据。

`resolveTaskProgression()` 返回 `execute-step`、`refine-discovery` 或 `complete`，但不直接修改 `OpsTask`。

### `src/features/agent/taskAdvancement.ts`

任务推进用例模块，负责：

- 在发现续规划前校验模型和 API Key 是否可用。
- 返回新增计划、自动审批判定、失败暂停原因和稳定事件消息。
- 在计划异步返回后检查取消状态，避免向已取消任务追加步骤。
- 组合任务完成总结及模型请求、模型返回、任务完成三类审计。
- 在总结异步返回后检查取消状态，不为已取消任务生成完成成功审计。

本模块不直接修改 `OpsTask`，状态提交、消息分发和持久化仍由 store 负责。

## 5. Pinia 状态协调

### `src/stores/ops.ts`

当前负责：

- 服务器、任务、模型、工具、日志、文件和指标状态。
- localStorage 持久化协调。
- 系统钥匙串数据加载和保存。
- 调用 Agent 纯规则和后端服务。
- 任务执行循环和各领域服务之间的异步用例协调。
- 接收智能需求控制台显式传入的任务 ID，并校验任务所属服务器后提交需求。
- 删除服务器时同步清理对应的智能需求工作区状态。

新增工具相关状态和 action：

- `tools`：合并默认目录和用户覆盖后的有效工具。
- `enabledTools`：已启用工具 getter。
- `saveTools()`：校验并持久化工具覆盖。
- `resetTool(toolId)`：恢复单个内置工具默认值。

## 6. 后端适配与 Rust

### `src/services/backend.ts`

前端唯一后端适配层：

- Tauri 环境调用 Rust command。
- 浏览器环境返回可测试的演示结果。
- 统一 DTO 和运行时参数。
- 监听 `sftp-transfer-progress` 并按 `transferId` 转发真实传输进度。
- 浏览器演示适配器使用同一传输回调契约。

文件结构入口：

```ts
backend.getRemoteFileStructure(connection, request)
```

该方法先执行前端规范化，再调用 `get_remote_file_structure`。

### `src-tauri/src/file_tree.rs`

远端文件结构工具的 Rust 领域实现：

- 使用 `ssh2::Sftp::readdir()`，不执行 shell `find`。
- 校验根路径、排除项、深度和节点数。
- 目录优先、名称稳定排序。
- 不跟随符号链接，防止循环和越界遍历。
- 子目录读取失败写入 warnings；根目录错误直接失败。
- 达到深度或节点上限时返回部分结果和明确标记。

### `src-tauri/src/credential.rs`

系统钥匙串模块，拥有以下职责：

- 校验 `server`、`model`、`secret` 三类凭据命名空间。
- 生成隔离的钥匙串账户名。
- 实现 `save_credential`、`load_credential`、`delete_credential` 三个 Tauri command。
- 空值保存等价于删除，不存在的凭据删除保持幂等。

拆分后 command 名称和前端参数未改变。

### `src-tauri/src/command_guard.rs`

Rust 命令风险策略模块。统一为真实 SSH 执行器、演示执行器和计划风险归一化提供风险分类；`requires_high_risk_approval()` 保证已知破坏性命令没有单独批准时不能执行。

### `src-tauri/src/json_contract.rs`

模型 JSON 契约解析模块，负责：

- 移除模型偶尔返回的 Markdown JSON 代码块外壳。
- 仅在 JSON 字符串内部修复 Shell 合法但 JSON 非法的反斜杠转义。
- 按标准 JSON、修复后标准 JSON、JSON5、修复后 JSON5 的顺序解析。
- 泛型支持直接数组和指定对象数组字段，不依赖 `AiPlanStep` 等模型 DTO。
- 同时保留标准解析与宽松解析错误，便于日志定位真实格式问题。

### `src-tauri/src/model.rs`

模型传输与可用性模块，负责：

- 创建带超时的 HTTP 客户端并发送模型请求。
- 对网络错误、响应读取不完整、非法 JSON、HTTP 429 和服务端错误执行有限重试。
- 从兼容 Chat Completions 的响应中提取首个助手消息内容。
- 查询模型列表并区分配置缺失、接口错误、空列表、模型不存在和模型可用。

`generate_ai_plan`、`process_ai_requirement`、`generate_ai_summary`、`review_ai_step` 和 `check_ai_model` 的 Tauri command 名称及参数均未改变。

### `src-tauri/src/ssh.rs`

SSH 连接与命令执行模块，负责：

- 解析服务器地址，并为 TCP 连接、读取和写入设置明确的超时边界。
- 建立 SSH 会话、完成密码认证，并统一连接和认证错误语义。
- 执行非流式命令，按标准输出、标准错误顺序合并结果。
- 使用 POSIX 单引号规则转义远端 Shell 参数，严格校验执行 ID，并生成隔离的远端 PID 文件路径。
- 使用 `setsid` 包装流式命令，通过 PID 文件支持远端进程组取消；主动取消统一返回退出码 `130`。
- 通过回调上报标准输出和标准错误，不依赖 Tauri 事件类型，便于独立测试和后续复用。

`execute_ssh_command` 等 Tauri command 的名称和参数未改变；事件发送、运行状态管理和 command 注册仍由 `lib.rs` 负责。

### `src-tauri/src/terminal.rs`

SSH PTY 终端模块，负责：

- 使用线程安全的会话表管理终端 ID 与输入通道，重复启动同一 ID 时保留已存在会话。
- 处理文本输入、终端尺寸调整和主动关闭三类内部消息。
- 建立远端 `xterm-256color` PTY，并持续转发标准输出、标准错误和系统状态事件。
- 将终端线程的连接、输入、输出、缩放和清理错误映射为明确的中文错误信息。
- 为每次会话注册分配递增代次，线程结束时只清理自己的代次，避免旧线程误删快速重连的新会话；关闭不存在的会话保持幂等。
- 发送携带会话代次的 `terminal-status` 事件，区分连接中、已连接、主动关闭、远程 EOF 和连接错误。
- 认证失败标记为不可重试，远程 EOF 和网络错误标记为可重试。

`start_ssh_terminal` 现返回会话代次；`write_ssh_terminal`、`resize_ssh_terminal` 和 `close_ssh_terminal` 参数保持不变。`TerminalManager` 仅向 `lib.rs` 暴露注册应用状态所需的类型。

### `src-tauri/src/sftp.rs`

现有 SFTP 功能的结构模块，负责：

- 统一创建已认证的 SFTP 会话，并保留既有中文错误语义。
- 将远端目录项映射为 `RemoteFileEntry`，目录优先并按名称稳定排序。
- 执行目录创建、条目重命名、空目录或文件删除，以及文件读取和写入。
- 保留根目录删除保护与 20 MB 上传、下载限制。
- 将文件类型判断、大小显示、目录项映射、排序和限制校验拆成可独立测试的纯辅助逻辑。

六个 SFTP command 的名称、参数和返回结构未改变。该模块只规范当前代码边界；SFTP 后续整体重做时，可以替换模块内部实现而不影响 `lib.rs` 的 command 注册层。

### `src-tauri/src/sftp_transfer.rs`

SFTP 传输协议与运行状态模块：

- `SftpTransferManager` 使用线程安全任务表管理取消标记，重复 `transferId` 会被拒绝。
- 上传和下载每 64 KiB 检查取消状态，并发送 `sftp-transfer-progress` 字节事件。
- 取消上传会在关闭文件后尽力删除远程部分文件。
- command 在 Tauri 阻塞线程上执行 SSH/SFTP I/O，不阻塞异步运行时。

当前 `upload_sftp_transfer` 仍接收完整字节数组，`download_sftp_transfer` 仍返回完整字节数组，因此保持 20 MB 上限。大文件支持必须在后续改为本地文件路径流式传输。

### `src-tauri/src/metrics.rs`

本地与远端指标模块，负责：

- 定义前端所需的 `Metrics` 序列化 DTO。
- 为非真实连接场景生成现有本地演示指标。
- 通过 SSH 采集 CPU、内存、磁盘和网络累计字节，并解析为稳定返回结构。
- 按服务器连接标识保存上一轮网络累计值，根据采样间隔计算 MiB/s；首次采样返回零速率。
- 对百分比执行舍入与 `0..100` 边界约束，网络计数器回退时不产生负速率。

`get_realtime_metrics` 和 `get_ssh_metrics` 的名称、参数及返回字段未改变。采集命令、输出解析和采样状态均由本模块拥有。

### `src-tauri/src/lib.rs`

当前仍是主要 Tauri command 注册和既有后端实现文件。新增 command：

```text
get_remote_file_structure
```

它负责组合已拆分模块并注册 Tauri command。文件结构、凭据、命令风险、JSON 契约、模型传输、SSH 执行、终端 PTY、SFTP 和指标均已迁出；当前保留共享用例 DTO、服务器探测、智能任务入口和演示适配器。

### `src-tauri/src/tests.rs`

Rust crate 普通回归测试模块，覆盖计划字段修复与必填约束、可选输出长度限制、步骤数量限制、需求分类结构、查询空结果语义和演示高危审批门禁。该模块不访问网络或外部凭据，默认随 `cargo test --lib` 执行。

### `src-tauri/src/live_tests.rs`

真实环境集成测试模块，负责：

- 使用模型测试 Key 验证真实计划生成与非空命令结构。
- 使用隔离 SSH 服务器验证探测、命令执行、PTY、SFTP 生命周期和远端指标。
- 集中读取 SSH host、port、user 和 password；端口未配置时使用 `22`。
- 支持覆盖兼容模型端点和模型名，便于在隔离或自建模型环境验收。
- 使用清理守卫在测试异常退出时尽力回收 SFTP 临时文件和目录；正常删除验证完成后停用守卫，避免重复连接。
- 通过 `#[ignore]` 隔离外部副作用，只在显式提供 `OPSARK_TEST_*` 变量并指定 `--ignored --exact` 时执行。

测试名称保持为 `live_tests::generate_live_deepseek_plan` 和 `live_tests::probe_live_ssh_adapter`，与 README 验收命令一致。

## 7. 审计与敏感数据

`AuditEvent.category` 新增 `tool`。工具日志包含：

- `toolId` 和 `callId`。
- 脱敏调用参数。
- 结果摘要、截断状态和 warnings。
- 执行耗时。

禁止写入日志：

- SSH 密码。
- 模型 API Key。
- 敏感变量真实值。
- 合并敏感值后的真实命令。

文件结构工具参数目前只有路径和遍历限制，不包含文件内容或连接密码。
