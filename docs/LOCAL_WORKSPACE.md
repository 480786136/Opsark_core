# Local 工作台

左上角 Logo 指向 `/workspace`：恢复已打开标签中的活动工作台；没有打开的标签时进入 `/local`。已配置但已关闭的服务器不会因旧路径记录而重新打开。侧栏服务器管理入口仍为 `/`。

Local 与服务器作为同一列表中的标签，使用相同的选择、关闭和“＋”重新打开入口。重新打开的标签追加到列表末尾；关闭活动标签时优先切换到右侧相邻标签，再尝试左侧。关闭最后一个服务器后默认打开 Local；仅剩 Local 时保留此标签。普通切换保留终端会话，明确关闭 Local 则释放缓存与本地会话，再次打开时创建新会话。Local 不写入服务器配置列表，也不复用远程 Agent、SFTP 或监控的连接。

Local 与服务器共用 `WorkspaceNavigation`，统一标签顺序、尺寸、高亮与关闭行为。长名称省略显示；首次进入、切换或从缓存恢复时，将当前标签滚动到可见区域。服务器选择菜单相对整条导航定位，避免窄屏时超出页面边界。

标签状态统一保存到 `opsark.workspaceTabs.v2` 的 `openTabs` 和 `activeTabId`，自动迁移旧服务器标签记录。只有成功提交的路由可以打开、激活标签；缓存视图不再用旧服务器 ID 写回标签列表。连续关闭通过同一路由队列顺序执行，关闭活动标签前先完成相邻标签跳转，避免尚未完成的跳转重新打开刚关闭的服务器。导航被阻止时保留当前标签及其会话。

开发热更新期间，已缓存的旧 Local 页面可能仍保留 `.local-tabs` 结构。全局加载的 `legacyWorkspaceTabs.css` 为这类旧结构保留样式，避免组件样式替换后退化为普通链接；选择器不匹配新版导航。这层兼容只调整外观，不通过刷新或重新挂载终端来恢复样式。

导航验收应包含多标签末尾直接进入、Local → 服务器 → Local 的缓存恢复、快速连续关闭全部服务器、关闭后从 Logo 或刷新恢复、Local 关闭与重新打开、长名称、深浅主题与窄屏菜单；除显示正确外，还需确认普通切换保留终端实例、明确关闭后释放实例。旧 DOM 的兼容样式可用独立浏览器夹具检查，桌面会话仍需在客户端中验收。

本地终端使用 [portable-pty](https://docs.rs/portable-pty/0.9.0/portable_pty/) 和 xterm。Windows 启动 PowerShell；macOS 使用 SHELL 指定的登录 Shell，默认 zsh。工作目录为用户主目录，权限与应用进程一致。浏览器预览不执行本机命令，显示桌面端提示。

支持实时输入、控制字符、字节流输出和尺寸同步。Windows 启动期间保留 xterm 的光标位置回应；会话退出由独立进程监视线程回收，读取线程持续读取退出输出，避免 ConPTY 关闭时阻塞。

需要重启 Tauri 开发进程或重新打包。Windows 本地 PTY 冒烟测试覆盖真实 Shell 输出及尺寸调整；macOS 仍需实机验收。
